# Mac 真机验收清单

每个版本发布前，在 macOS 真机上逐项确认（计划 Q-02）。组件测试已经覆盖逻辑，这份清单只关心**真机上的行为**：菜单栏、快捷键、输入法、拖拽、沙盒、签名，以及旧数据升级。

## 怎么做

1. 从要发布的提交构建 Release 版，按 `Release` 工作流的方式签名（先 `--deep` 签内部代码，再带 `Release.entitlements` 签整个应用）。
2. 不要碰日常使用的数据：把 `apps/marginmind/macos/Runner/Configs/AppInfo.xcconfig` 里的 bundle ID 临时改成 `io.github.mylxsw.marginmind.reviewNNN`。应用是沙盒应用，换了 ID 就有独立的数据容器。验收完删除构建产物，不要提交这处改动。
3. 数据格式有变化的版本，先用**上一个发布标签**以同一个临时 bundle ID 构建，在空资料库里做出旧数据（见“数据迁移”），退出后再换成要发布的构建。两个构建的 bundle ID 相同，启动前用 `lsregister -u` 注销旧构建，避免系统打开错的那个。
4. 从空资料库开始，打开示例学习集，按下表顺序操作。
5. 结果写在文末的“验收记录”里：✅ 真机通过；🧪 真机上无法自动操作，由组件测试覆盖，有条件时再手动看一眼；❌ 不通过（附问题和修复 PR）。

## GUL-495：项目所有者最终验收（不阻塞 PR 合并）

- [ ] **触控板手感**：Retina 全屏，在图片型或扫描 PDF 与至少 300 节点脑图的分屏中连续滚动、慢速逐页阅读和双指缩放。确认无明显停顿、白页或长期模糊；记录机器、文档、录屏与主观手感。滚轮自动化和 FrameTiming 数据仅作为佐证。
- [ ] **物理 ⌘0 与原生菜单匹配**：阅读器放大后点击阅读器并按 ⌘0，应恢复实际大小；脑图缩放或平移后点击脑图并按 ⌘0，应适应窗口。多次切换焦点，确认禁用菜单项不会吞掉另一项的按键；文本编辑时也检查不会意外缩放。
