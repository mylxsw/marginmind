## 0. 一页结论

- **方向同意，有两处建议调整。** 支持 EPUB、MOBI、Markdown 和网页的方向是对的；Markdown 先做“只读”也对。需要调整的是**电子书怎么渲染**和**网页什么时候提示转换**。
- **EPUB / MOBI：先排版成页面，再复用 PDF 阅读器。** 不另写一套“流式阅读器”。导入时用系统 WebKit 把电子书排成 PDF 渲染件（原文件完整保留），之后划线、批注、摘录、画笔、裁边、对照阅读、助手、卡片回原文全部现成可用。字号、页面大小可以调，调完重新排版；标注同时记录**原文位置**（章节 + 字符偏移 + 引文），重排后自动对齐，不依赖页码。
- **MOBI / AZW3 不单独做渲染。** 导入时解包成 EPUB 结构（KF8 直接提取，旧 MOBI 解压 HTML），之后和 EPUB 走同一条路。受 DRM 保护的文件明确拒绝。
- **Markdown：原生渲染，只读。** 支持目录、搜索、复制、问助手；高亮、批注、摘录、画笔置灰并说明原因。以后需要标注时，可以“生成可标注副本”（走同一条排版流程），不在本期。
- **网页：内置浏览器打开 → 检测就绪 → 非模态提示 → 转换。** 渲染完成的提示做成从“转换为文档”按钮弹出的气泡，**不用模态弹窗**：很多页面要先登录、关 Cookie 横幅或滚动加载，模态框会打断这些操作。默认转换为 **PDF · 阅读模式**（Readability 提取正文后排版，可标注）；也可以选原网页样式 PDF 或 Markdown（只读）。来源网址、抓取时间、网页快照一起保存，可以“重新抓取”。
- **一条排版管线服务三种来源。** EPUB、MOBI、网页阅读模式都是“HTML → 应用排版样式 → WebKit 分页打印 → PDF 渲染件”。这是本方案最核心的一块，也是最大的技术风险，建议第一步先做技术验证。

## 1. 对原方案的分析

| 原方案 | 评价 | 调整 |
| --- | --- | --- |
| 支持 MOBI、EPUB | 需要。难点不在“打开”，而在**现有工具都绑在 PDF 页坐标上**：`Annotation` 存的是 `page + PageRect`，裁边、页边批注、对照阅读、OCR、区域摘录、卡片回原文都依赖它 | 不做第二套流式阅读器，排成页面后复用 PDF 链路；标注额外记录原文位置，保证重排后不丢 |
| 支持 Markdown，先只读 | 同意。Markdown 没有固定页面，锚点要按块和字符偏移做，且源文件可能被外部修改 | 只读；选中文字可复制、问助手（不建锚点）；以后可选“生成可标注副本” |
| 输入网址 → 内置浏览器渲染 | 同意。内置浏览器能处理登录、懒加载、SPA，比后台抓 HTML 可靠 | 在原文栏以“浏览器标签”打开，侧栏标“未保存” |
| 渲染完成后**弹窗**询问是否转换 | “加载完成”≠“内容就绪”：懒加载图片、SPA、登录墙、Cookie 横幅都会让首次完成事件早于用户真正想要的状态；模态弹窗还会挡住这些操作 | 就绪检测（加载完成 + 网络与 DOM 静默 800ms，上限 15 秒）后，从“转换为文档”按钮弹出**非模态气泡**；按钮常驻，任何时候都能转换 |
| 转换为 PDF 或 Markdown | 同意两种格式，但“PDF”需要再分：直接打印网页常带导航、广告、侧栏，页面断裂难读 | PDF 分“阅读模式（推荐）”和“原网页样式”；Markdown 只读 |
| 保存到当前项目，之后可标注 | 同意 | 同时保存来源网址、抓取时间、快照；顶部来源条可“打开原网页”“重新抓取” |

### 1.1 为什么不做流式（reflow）阅读器

流式阅读器（像 Apple Books 那样随窗口重排）体验更好，但代价是：

1. 现有所有阅读工具都要在第二套渲染器上重写一遍（高亮、下划线、页边批注、画笔、裁边、对照阅读、OCR、区域摘录、选区工具条、页码导航、书签目录）。
2. macOS 上 Flutter 与原生 WebView 叠加交互（浮动工具条、拖选、页边批注连线）问题多，容易出现事件和层级 bug。
3. 两套渲染器意味着以后每个阅读功能都要做两遍。

排版成页面的代价是：重排需要几秒；页面大小固定，窗口变化不会实时重排（用“适合窗口”页面尺寸缓解）。对一个以“标注 → 脑图”为核心的应用，这个取舍是值得的。如果以后确实需要流式阅读，原文位置锚点（第 4.2 节）已经为它预留了数据基础。

## 2. 用户场景

| 场景 | 用户想要什么 | 对应能力 |
| --- | --- | --- |
| 买了一本无 DRM 的 EPUB / AZW3 电子书 | 像读 PDF 一样划线、摘录到脑图 | 电子书导入与排版 |
| 字太小 / 想换个页面大小 | 调字号，不丢已有标注 | 调整排版 + 原文位置重新对齐 |
| 有一份 Markdown 讨论提纲、讲义 | 和其他资料放在同一个学习集里看 | Markdown 只读 |
| 读到一篇好文章 | 存下来，离线也能读，能划线 | 添加网页 → PDF 阅读模式 |
| 文章需要登录、有 Cookie 弹窗 | 先处理完，再转换 | 内置浏览器 + 非模态提示 |
| 文章后来更新了 | 获取新版本，旧标注不丢 | 重新抓取 |

## 3. 交互设计（对应原型场景）

原则：**不新增界面区域，只在现有位置上按格式替换或置灰。** 侧栏、标题栏视图切换、原文工具栏、页面侧栏、浮动工具条、脑图栏都沿用现在的样子，用户换一种文档不需要重新找按钮。

### 3.0 原文工具栏按格式（`reader_pane.dart` `_toolbar`，从左到右）

| 位置 | PDF（现状） | EPUB / MOBI / 网页（排版件） | Markdown |
| --- | --- | --- | --- |
| 1 页面侧栏 | 缩略图 / 目录 / 书签 / 标注 | 不变；目录来自书内 nav / NCX，页码为排版后页码 | 只有目录（标题）和书签，缩略图、标注置灰 |
| 2 页面（+/-） | 缩放滑块、实际大小 / 适合宽度 / 适合页面 | 不变 | 改为“字号”（较小 / 默认 / 较大） |
| 3 裁掉白边 | 裁边 | **换成“排版”(Aa)**：字号、页面大小、正文字体、重新排版。页边距由应用控制，裁边没有意义，所以占用同一位置 | 置灰 |
| 4 阅读外观 | 白色 / 黑暗 / 纸质 / 浅绿 | 不变 | 不变 |
| 5 工具组 | 选择、高亮、下划线、框选、画笔 │ 摘录同步到脑图 | 不变 | 只有“选择”可用，其余置灰，悬停说明“Markdown 暂不支持” |
| 6 页边批注 | 页边批注 | 不变 | 置灰 |
| 7 对照阅读 | 对照阅读 | 不变（可与 PDF 互相对照） | 置灰 |
| — | — | — | 追加“仅阅读”标签，点开说明能做与不能做的事 |
| 右端 切换文档 | 文档列表、关闭当前文档 | 列表里按格式显示图标；新增“导入文档…”“添加网页…” | 同左 |

- 侧栏“文档”列表：PDF 继续用文档图标，电子书用书本图标，Markdown 用 M↓ 图标，网页用地球图标；右侧数字是页数（排版件为排版后的页数，Markdown 不显示）。
- 浏览器状态下，原文工具栏整行换成浏览器栏：后退、前进、刷新 / 停止、地址栏、“转换为文档…”、关闭；右端仍是“切换文档”。
- 浮动工具条：排版件与 PDF 相同（颜色点、拷贝、批注、翻译、问助手）；Markdown 去掉颜色点和批注，只留拷贝、翻译、问助手。


### 3.1 入口（场景 1、2）

- 侧栏“文档”标题右侧现有的 **+**（导入文档…）改为菜单：**导入文档…**（⌘O，一个选择器支持 PDF、EPUB、MOBI、AZW3、Markdown）和**添加网页…**（⇧⌘O）。原文工具栏右端的“切换文档”菜单和文件菜单同步增加这两项。
- 从 Finder 拖入文件：窗口出现投放区，列出支持的格式；不支持的格式在投放区里直接提示。拖入网址（从 Safari 地址栏）等同于“添加网页”。
- 资料库“新建学习集”同样接受这些格式（以文档名命名学习集）。

### 3.2 EPUB / MOBI 导入（场景 2、3、7、8）

- 导入面板显示步骤：读取电子书（MOBI 多“识别格式”“解包为 EPUB 结构”）→ 排版为页面（按章节显示进度）→ 生成目录与页码。可以取消；取消后不留任何文件。
- 排版在后台进行，面板可关闭，侧栏条目显示进度圈。
- DRM、损坏文件、不支持的变体（KFX）：错误面板说明原因和替代方式，不写入任何文件。AZW4（Print Replica）内含 PDF，直接取出 PDF 导入。

### 3.3 电子书阅读（场景 4、5、6）

- 阅读体验与 PDF 一致：选中文字弹出浮动工具条，点颜色点摘录到脑图，卡片出处显示格式徽标和章节名。
- 工具栏第 3 个按钮（PDF 的“裁掉白边”）换成“**排版**”：字号（小 / 中 / 大 / 特大）、页面（适合窗口 / A5 / A4）、正文字体（宋体 / 苹方 / 原书）。点“重新排版”后显示进度 HUD，完成后提示“共 N 页 · M 处标注全部对齐”；有无法对齐的标注时提示“N 处需要确认”，列出供用户手动处理（不删除）。
- 第一页上方一行说明：原文件名、当前排版参数、“调整排版”。
- 目录来自电子书自带的 nav / NCX，页码是排版后的页码。

### 3.4 Markdown（场景 9、10）

- 原生渲染：标题、段落、列表、任务列表、引用、表格、代码块、图片、链接。宽度随窗口自适应，最大 720pt；“阅读外观”的四种纸色同样适用。
- 工具栏按 3.0 表置灰，追加“仅阅读”标签。
- 选中文字：工具条只有“拷贝”“翻译”“问助手”，并写明“Markdown 暂不支持划线”。问助手只带文字，不建立原文锚点。
- 本地图片：导入时把 Markdown 引用的相对路径图片一并复制进学习集。远程图片默认拦截（避免泄露阅读行为），点一下才加载。
- 链接：外部链接用系统浏览器打开；`#标题` 链接在文内跳转。

### 3.5 添加网页与内置浏览器（场景 11、12、15、16）

- “添加网页”面板只要一个网址输入框：自动补 `https://`；拒绝 `file:`、`javascript:`、`data:` 等非 http(s) 协议，错误直接显示在输入框下方。
- 网页在原文栏打开，原文工具栏换成浏览器栏（见 3.0）；载入进度显示在地址栏底部细线。侧栏“文档”下出现一条“未保存”的临时条目，点浏览器栏的关闭即丢弃。
- **就绪检测**：主框架加载完成，且网络请求和 DOM 变化静默 800ms 后，视为就绪。“转换为文档”按钮变为主色并轻微脉动，同时从按钮弹出气泡“页面已渲染完成，要转换为文档并保存到「学习集」吗？”［稍后］［转换为文档…］。点稍后或页面任意处，气泡收起，按钮常驻。
- **加载缓慢**：15 秒仍未静默（广告、评论、长轮询），气泡改为“页面还在加载部分内容……已显示的正文可以先转换”［继续等待］［转换为文档…］。
- **加载失败**：标签内显示原因（超时、无法解析域名、证书错误），提供“修改网址”“重试”；转换按钮禁用。

### 3.6 转换为文档（场景 13、14）

- 面板左侧实时预览，右侧：标题（默认取页面标题）、保存为（三选一）、“保存网页快照”（默认勾选）。
  - **PDF · 阅读模式（推荐）**：Readability 提取正文和配图，套用应用的阅读样式排版。可划线、摘录、批注。
  - **PDF · 原网页样式**：保持浏览器里的样子（先自动滚动触发懒加载，再分页打印）。可标注。
  - **Markdown**：正文转 Markdown，图片下载到本地。只读。
- 转换步骤：提取正文 → 下载图片 → 排版为 PDF（或转换为 Markdown）→ 保存到学习集。完成后关闭浏览器标签，打开新文档，侧栏条目短暂高亮。
- 网页文档工具栏与电子书相同（第 3 个按钮是“排版”）；第一页上方一行显示域名、抓取时间、保存方式，“打开原网页”（系统浏览器）、“重新抓取”（生成新版本，旧标注按原文位置对齐，对不上的列出来）。

## 4. 技术方案

### 4.1 数据模型（`mm_core`）

在 `Document` 上增加字段，旧数据默认值即当前行为（不需要迁移文件，只做 JSON 兼容读取）：

```dart
enum DocumentFormat { pdf, epub, mobi, markdown, web }

class Document {
  // 现有字段……
  final DocumentFormat format;        // 默认 pdf
  final String? sourceFileName;       // 原文件：documents/<sha>.epub / .azw3 / .md；pdf 为 null（fileName 即原文件）
  final Rendition? rendition;         // 排版件；pdf / markdown 为 null
  final WebOrigin? origin;            // 网页来源；其他格式为 null
}

class Rendition {
  final String preset;                // 'm/fit/serif' 等，字号/页面/字体
  final int version;                  // 每次重新排版 +1
  final String pageMapFile;           // 页 ↔ (章节 href, 字符偏移区间) 映射，JSON
}

class WebOrigin {
  final Uri url;
  final DateTime capturedAt;
  final WebCaptureMode mode;          // readable / original / markdown
  final String? snapshotFile;         // 网页快照（HTML + 资源清单），用于重新抓取 / 换格式
}
```

- `fileName` 继续指向**阅读用的文件**：PDF 为原文件，电子书和网页为排版出的 PDF，Markdown 为 `.md` 本身。这样 `mm_pdf` 和现有读取路径不需要感知格式。
- 新增 `DocumentCapabilities`（纯查询，按格式返回能力集合：标注、画笔、裁边、OCR、对照阅读、排版、重新抓取……）。UI 只读能力，不写 `if (format == …)`，以后放开 Markdown 标注时只改这一处。

### 4.2 原文位置锚点

```dart
class TextAnchor {
  final String section;   // EPUB spine href / 网页为 'main'
  final int start, end;   // 章节纯文本内的字符偏移
  final String quote;     // 现有 Annotation.quote
  final String prefix, suffix; // 前后各 32 字，用于模糊重定位
}
```

- `Annotation` 增加可选 `TextAnchor? textAnchor`。排版件上划线时，通过 `pageMapFile` 把 PDF 选区换算成原文位置一并保存；PDF 原生文档为 null。
- 重新排版或重新抓取后：先按 `section + start/end` 定位，校验 `quote`；不一致时在本章节内按 `prefix + quote + suffix` 模糊匹配；仍失败则标记“需要确认”，保留旧坐标，不删除。
- 页边批注、卡片“回原文”都走同样的重定位。

### 4.3 排版管线（核心；Dart 接口在 `mm_platform`，原生实现在 macOS Runner）

```
EPUB 解包 / MOBI 解包 / Readability 正文
        │  XHTML 章节 + 资源（图片、CSS、字体）
        ▼
注入应用排版样式（字号、行距、字体、页边距；保留书内必要样式，去掉固定宽度等破坏分页的规则）
        ▼
WKWebView 离屏加载（本地资源，禁 JS 网络、禁外链）
        ▼
NSPrintOperation 分页输出 PDF（每章一段，合并）＋ 记录每页首尾文字 → pageMapFile
        ▼
documents/<sha>.r<version>.pdf  → 现有 mm_pdf 读取
```

- 按章节分段排版，进度可报告、可取消；合并用 PDFium。
- 目录：EPUB nav / NCX 的章节锚点在排版时记录页码，写成 `DocumentOutline`（复用现有目录与书签功能）。
- 固定版式 EPUB（漫画、绘本）：每个页面按原尺寸打印一页，不注入排版样式。
- 原生通道 `marginmind/typeset`，接口与 `ArticleParserChannel` 同风格（job id、cancel）。Windows（WebView2 `PrintToPdfAsync`）/ Linux（WebKitGTK 打印）作为跨平台计划的后续任务，未实现的平台用能力开关隐藏“导入电子书 / 添加网页”。

### 4.4 解析

- **EPUB**：`archive` + `xml`（已是传递依赖，改为直接依赖），读取 `container.xml` → OPF（spine、manifest、metadata）→ nav / NCX。检测 `META-INF/encryption.xml` 中的非字体加密即判定 DRM。
- **MOBI / AZW3**：纯 Dart 解析 PalmDB 记录与 MOBI/EXTH 头。KF8（AZW3、新 MOBI）：按 FDST / skeleton / fragment 还原 XHTML 与资源；MOBI6：PalmDOC / HUFF-CDIC 解压出 HTML，`filepos` 链接转锚点。输出与 EPUB 解析相同的中间结构。PalmDOC 头的加密类型非 0 → 判定 DRM，拒绝。KFX 不支持（格式私有），提示用户先转换。
- **Markdown**：复用应用已有的 `markdown` 包解析为 AST，Flutter 组件渲染；扫描相对路径图片随文档复制。代码高亮、数学公式不在本期。

### 4.5 内置浏览器与网页抓取

- macOS 用原生 `WKWebView`，以 Flutter 平台视图嵌入原文栏。**技术验证点**：平台视图上的浮动气泡、HUD 叠加是否正常；若不理想，退回“独立浏览器面板窗口”，交互不变。
- 隔离：独立的 `WKWebsiteDataStore`（与 Safari 隔离、可在设置中清除，保留登录态以便处理需要登录的页面）；注入脚本运行在独立 `WKContentWorld`，页面拿不到任何应用桥接；禁止下载、禁止 `file:`/自定义协议导航、新窗口在本标签打开。用户主动浏览允许访问内网地址（与助手抓取的 `url_policy` 不同，助手抓取规则不变）。
- 就绪检测：注入脚本统计未完成请求（`PerformanceObserver` + fetch/XHR 计数）与 `MutationObserver` 静默期，上报给 Dart；上限 15 秒。
- 抓取：从当前 WebView 取序列化后的 DOM（包含登录后、懒加载后的内容）——不重新请求网址。阅读模式复用现有 `ArticleParserChannel` 的 Readability 脚本；图片通过同一 WebView 会话下载到本地。
- 快照：`web/<sha>/index.html` + 资源清单，存入学习集包；重新抓取时生成新版本，旧版本保留到用户删除。

### 4.6 存储与导出

- 学习集包新增 `documents/<sha>.epub|.azw3|.md`（原文件）、`documents/<sha>.r<n>.pdf`（排版件）、`web/<sha>/`（快照）。旧版本排版件在新版本对齐完成后删除。
- 导出脑图、复习、搜索不受影响；搜索对 Markdown 用原文，对排版件用 PDF 文本层。
- 文件 › 导出文档：电子书可导出原文件或排版 PDF；网页可导出 PDF / Markdown。

## 6. 需要你确认的决定

1. **电子书走“排版成页面”路线**（而不是流式阅读器）。
2. **网页就绪提示做成非模态气泡**（按钮常驻），而不是模态弹窗。
3. **网页默认保存为 PDF · 阅读模式**，另提供原网页样式 PDF 与 Markdown。
4. **Markdown 只读时允许“拷贝”和“问助手”**（不建锚点）；“生成可标注副本”留到后续。
5. **内置浏览器保留登录态**（独立于 Safari、可在设置中清除），还是每次都用无痕会话。
6. 首期平台范围：**只做 macOS**，Windows / Linux 跟随跨平台计划。
