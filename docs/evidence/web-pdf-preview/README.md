# 网页保存弹窗的 PDF 预览修复

## 原因与处理

旧预览读取 `MMPdfEngine.inspectData` 生成的首页 PNG；该图固定宽 400px。它被放大到整栏显示，所以模糊，而且没有后续页面。文档包中保存的原始 PDF 完整，不需要修改抓取或保存格式。

新预览从文档包读取原始 PDF，通过 `MMPdfDataPreview` 打开。使用懒加载页面列表，按每页比例适配栏宽，由 PDFium 按布局尺寸和屏幕像素密度渲染（上限沿用 pdfrx 的 300dpi）。窗口宽度变化会重新渲染；只保留附近页面，不把整本 PDF 一次转成大图。预览继续允许滚动且不绘制滚动条。阅读和 Markdown 预览保持原有布局。

## 验证

- 应用转换、布局和文档包：13 项测试通过。
- PDF 层的预览、缩略图和缓存：11 项测试通过。新回归在 2× 像素密度、600pt 宽度下请求 1200px 页面；改变宽度后请求 1600px 页面；能滚动到第 50 页，而且初始没有构建全部 50 页，也没有滚动条。
- macOS 原生集成测试通过，实际打开三页中文 PDF，渲染首页并滚动到第 3 页，切到 Markdown 后重新打开 PDF，再取消关闭。首末页实际位图均为 1287×1665px，与 643.5pt × 2 的预览宽度一致。
- 定向静态分析通过；macOS Debug 原生测试构建成功。
- 原生截图：`first-page.png`、`last-page.png`。

复现命令（应用目录）：

```sh
MM_PDF_PREVIEW_EVIDENCE=web-pdf-preview flutter test integration_test/web_pdf_preview_test.dart -d macos --no-pub
```

截图先写入应用沙盒的临时目录，命令日志会打印位置，再复制到本目录。

边界：原生验收使用仓库三页中文 PDF，经同一转换器和保存弹窗加载；没有重新抓取用户截图中的微信公众号文章，也没有替换已安装的发行版应用。
