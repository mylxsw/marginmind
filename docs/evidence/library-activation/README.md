# 首页学习集打开修复（2026-11-01）

## 发现与改动

- 这台 Mac 的 `NSEvent.doubleClickInterval` 实测为 0.5 秒；Flutter 的 `kDoubleTapTimeout` 为 300 毫秒。原首页使用 Flutter 默认识别器，因此相隔 300～500 毫秒的点击无法打开。现在从 macOS 读取系统间隔，应用重新激活时刷新，通过输入状态传给鼠标双击识别器；触摸仍使用原间隔。
- 原先单击选中需要等待双击判断。图标和列表改为单击释放时立即选中，第二次点击打开，继续保留子级收藏按钮和拖动的事件处理。
- 原先导航必须等待 `markOpened`，该方法会保存学习集文件。现在先切换页面，再保存最近打开时间；保存失败仅记录日志，旧保存完成后也不会切换页面。最近打开时间可能在写入失败时不更新，学习集内容保存逻辑不变。

## 验证

- 修复前，封面、标题、说明文字、左上边缘、底部空白五个区域，分别使用快速释放和按住 120 毫秒的鼠标双击，10 项测试均通过；未发现固定点击死区。单击立即选中的测试在修复前失败。
- 修复后，以上区域、图标/列表的 400 毫秒双击、收藏按钮、单击选中、模拟慢速/失败时间戳写入、返回首页后旧写入完成的测试均通过。
- 首页、手机/平板首页、导图画布和键盘回归测试通过。设计组件的输入、触摸、无障碍测试，以及平台设置读取和更新测试通过。
- 修改的 Dart 文件静态检查通过；`flutter build macos --release --no-pub` 通过，使用 Flutter 3.47.6。
- 使用独立 bundle ID `io.github.mylxsw.marginmind.library-activation-qa` 的本地验证版和两个空白测试学习集，实际验证了图标双击打开、返回首页、切换列表、列表双击打开。正式应用及其数据未替换。

## 验证边界

400 毫秒的精确间隔由自动化界面测试验证；原生桌面操作验证了正常双击流程，没有测量输入事件间隔。隔离版首次尝试“打开示例学习集”返回通用失败提示，因此原生验证改用预置空白数据；没有用它证明 PDF 导入或真实文档阅读正常。

尚未复现用户描述的其他随机整页卡死。慢速/失败保存测试证明已解除首页导航对时间戳保存的等待，不能据此断言它就是此前卡死的唯一原因。
