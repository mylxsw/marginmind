# 二期开发需求：内容增强与阅读研究

> 建立日期：2026-10-26。状态：需求已整理，尚未实施。
> 本文合并两轮产品讨论：竞品页面对比后的内容增强清单，以及围绕 PDF / 脑图的 Research 方案。
> 二期是一个分批交付的需求集合，不等同于单个版本；以下顺序是默认实施建议，不代表已承诺版本号或工期。不得将本文的待办视作已经完成。

## 1. 目标与边界

让用户完成“阅读 → 发现疑问 → 查找资料 → 判断依据 → 整理为注解或脑图 → 后续回顾”，同时补足长内容阅读、外部图片、扫描文档、批注和分享能力。

产品继续以 Mac、本地优先、原文可追溯为基础。研究不只是内嵌搜索网页，成果必须能保存、定位和复用。不依赖 AI 也能搜索、阅读、摘录与保存。

已具备并应复用：PDF 分栏、多文档、多脑图、文字与区域摘录、原文与卡片双向定位、大纲、关联线、概要、标签、撤销、自动保存、FSRS 复习、Markdown / OPML 导出。不要重复实现这些功能。现状以实际代码为准，见 [项目计划](project-plan.md) 与 [架构](architecture.md)。

竞品截图仅是交互参考：不能据图标推断它支持任意视频字幕、自由白板、全文提取或 AI。以下是我们自己的需求，不是竞品能力承诺。

### 实施约定

- 优先交付完整的小流程，不用只有按钮或假结果的界面宣称完成。
- 复用设计令牌、组件、菜单命令、ARB 多语言和已有持久化机制；遵守 [CONTRIBUTING](../CONTRIBUTING.md)。
- 本文新增的基础圈画批注进入二期；旧计划 L-06“优先级最低”保留为一期历史，完整手写系统仍后置。
- 多窗口、SQLite 迁移、iCloud 同步、签名公证不因二期自动进入范围，也不是 Research 前置条件。

## 2. 内容增强功能清单

所有条目初始状态均为待开发。高 / 中 / 低表示相对产品优先级，不要求一次全部发布。

| ID | 优先级 | 功能与范围 | 验收标准 |
| --- | --- | --- | --- |
| P2-C01 | 高 | 卡片全文查看：长摘录、长标题可展开 / 收起，或在详情中完整查看 | 超过当前显示上限的内容可读全；不修改摘录原文；关闭后保留脑图位置；键盘可访问；不引发布局重叠 |
| P2-C02 | 高 | 外部图片卡片：粘贴截图、拖入或选择 PNG/JPEG，预览、缩放、加入脑图和复习 | 图片复制进学习集；原文件删除后仍可看；无 PDF 来源也能正确展示与复习，不显示假的“回原文”；导入可撤销，重启后保留 |
| P2-C03 | 高（按场景提前） | 扫描 PDF 文字识别：按页 / 按需识别，支持选字、搜索、摘录 | 识别文本与页上区域对应；摘录能回到正确位置；中文和英文样本验证；保留原 PDF；已有文本层避免重复识别；显示进度、错误并可取消 |
| P2-C04 | 中，首批候选 | 基础圈画：自由线、圈画、箭头、颜色、粗细、橡皮擦 | 笔迹绑定 PDF 页面坐标；缩放、滚动、重开不漂移；擦除和绘制可撤销；不妨碍文字选择；不要求压感或复杂笔刷 |
| P2-C05 | 中 | 脑图导出 PNG / PDF：整图或指定分支 | 包含卡片、图片、关联线、概要；不裁切、字体可读；大图有尺寸限制和清晰提示；保留已有 Markdown / OPML 导出 |
| P2-C06 | 中 | 卡片宽度调整、紧凑 / 完整显示 | 调整后连线与布局正确；测量缓存失效正确；显示偏好可恢复；正文不因视图变化被改写 |
| P2-C07 | 中 | 笔记基础格式：加粗、斜体、有序 / 无序列表 | 编辑、预览、保存和导出一致；旧纯文本笔记无损；不混淆原文摘录和用户笔记 |
| P2-C08 | 低 | PDF 页面文字批注：在指定位置添加、移动、编辑说明 | 使用页面坐标；重开位置一致；支持撤销；与研究注解共用内容能力，但允许独立创建 |
| P2-C09 | 低 | 批注套索：选择多条笔迹、移动、删除 | 仅处理明确选中的笔迹；批量操作一次撤销；不误改 PDF 内容；依赖 C04 |
| P2-C10 | 低，后置探索 | 自由白板：自由摆放卡片，切换自动 / 自由布局 | 保存独立位置；切换不丢节点、关系和原布局；多图互不污染；实施前补布局与坐标设计，不作为研究首版前置 |

C01、C02、C04 是内容增强首批建议；若实际用户主要读扫描教材，将 C03 提前。C03 不阻塞有文本层 PDF 的研究流程。图片复习题面需针对无 PDF 来源设计，不直接套用“遮住原文页”的现有规则。

## 3. Research 用户流程

### 3.1 入口与任务意图（P2-R01）

PDF 选区工具栏、已有高亮菜单、脑图节点菜单均提供“研究”；菜单命令集中注册，快捷键在核对现有占用后选择。

| 操作 | 默认目标 |
| --- | --- |
| 解释概念 | 结合上下文解释术语，提供例子 |
| 解读这段 | 拆开论点、推理和隐含前提 |
| 查证观点 | 查找依据、反例、适用条件 |
| 找视频 / 图解 | 查找更直观的讲解 |
| 找论文 | 查找相关研究、结论与局限 |
| 深入研究 | 自定义问题、多次检索与追问 |
| 翻译并解释 | 保留原文，给出译文和术语说明 |

用户可以编辑问题和搜索关键词；不要把整段原文机械地作为唯一搜索词。脑图多选支持比较节点，放在研究扩展批次交付。尚未接通的动作不作为可用入口展示。

### 3.2 研究侧栏与上下文（P2-R02）

- 顶部固定研究问题、触发选区、文档 / 页码或节点路径，并能回到起点。
- 主要视图为“解答 / 资料 / 已摘取”；文章阅读在面板内进入、返回，保留阅读位置。
- 从 PDF 发起默认保留原文、暂收脑图；从脑图发起保留脑图。窄窗口先收资料库侧栏，不硬挤四栏；关闭后恢复先前布局、缩放和位置。
- 默认上下文为选区及必要相邻段落，或节点及父级主题；用户可以查看和调整将发送的上下文。整篇文档不默认上传。
- 新选区不能改变正在运行的研究绑定；提供“新研究 / 加入当前问题”。异步响应按会话和请求标识归属，不能写入后来选中的节点。
- 普通查询、直接 AI 解答和资料阅读共用侧栏，不另造多个互不相通的聊天窗口。

### 3.3 搜索与来源（P2-R03）

支持网页、视频、论文、图片分类，平台、语言、时间过滤逐步补齐。按任务选择默认来源，不默认对所有平台同时搜索。

结果显示标题、作者 / 机构、网站、日期（未知就不显示确定日期）、摘要、相关性说明、打开原文、加入资料、稍后阅读。提供读取状态：未读取、仅搜索简介、仅摘要、已提取正文、已取得字幕、读取失败。

- 同 URL、同 DOI 或明确转载应去重 / 分组；不要将转载算作多份独立证据。
- 网页搜索首版至少接通一个真实可用渠道；不能只用演示数据验收。
- 学术来源优先使用结构化检索，展示作者、年份、摘要、DOI、全文入口和可获取状态；仅摘要不能冒充读过论文全文。
- 视频支持 YouTube、B 站的搜索与链接保存；有条件获取字幕时再开启基于字幕的总结。接入失败可打开平台搜索页，但必须标明这是外部搜索，不能假装已聚合读取结果。
- 图片搜索后续支持来源、预览和保存；显示来源信息，不把搜索缩略图冒充原图。

### 3.4 正文阅读与内容提取（P2-R04）

网页正文提取 → 结构化清理 → Markdown → 本地阅读。保留标题、段落、列表、表格、代码、图片说明与链接，移除导航广告。Markdown 是阅读与保存形式，不能丢失用于引用定位的段落标识。

原文提取不得用 AI 自由改写；翻译、摘要、解释单独呈现。失败时允许打开原网页、粘贴正文、只保存链接。受限内容不承诺全文；不绕过登录或付费限制。图片加载失败不影响已有文字阅读。

视频内容以可获取字幕及时间戳为依据；保留字幕语言和来源。没有字幕时只提供链接、简介与用户手写笔记，不生成“完整视频总结”。

### 3.5 AI 的三种范围（P2-R05）

| 范围 | 输入与标识 |
| --- | --- |
| 直接问 AI | 用户允许的上下文；明确“未联网”，不生成虚假外部引用 |
| 基于资料回答 | 用户勾选且实际读到的资料；列出参与回答的来源与读取范围 |
| 联网研究 | 搜索、读取、回答；显示进度和实际使用来源；读取失败不应被当成证据 |

无需配置 AI 也能完成手动搜索、阅读和摘录。AI 输出按需包含简短结论、关键解释、证据、不同观点 / 限制、待解决问题；不要求每个小问题都生成长报告。

每条要点可勾选、编辑、追问、保存。引用绑定具体片段；无依据则说明，不输出无法验证的精确置信度。用户改写结论时保留其编辑身份与原引用；新生成回答不覆盖已经保存或手改的结论。

首版 AI 提供者、模型、搜索服务及收费方式尚未指定。采用可替换接口；编码前以可用性、权限、成本、中文效果验证选型，记录决定。不得把某一家平台或全部用户自带 Key 当成已确认产品决策。Key 放系统安全存储，不进入学习集、导出或日志。

### 3.6 摘取与保存（P2-R06，首版必须完整）

允许手动划选正文、选择 AI 要点，保存前编辑标题和内容，选择：

1. 附到 PDF 原文：选区出现注解标记，点击查看；保存于学习集，首版不修改原 PDF。
2. 加入脑图：放到当前节点或指定分支，可合为一张卡或拆为多个子节点。
3. 同时保存：两处引用同一条研究笔记，编辑同步，不复制成互相脱节的两份文本。

默认保存到研究发起位置。脑图仅展示简短结论，完整内容和引用用 C01 的详情能力查看。一次保存及关联操作作为一次可撤销编辑；重复点击不能重复创建。

研究笔记不是聊天记录本身；只保留用户明确选入的成果。聊天 / 查询历史可继续存在，但不自动全部进入 PDF、脑图和复习队列。

### 3.7 中断、恢复、回顾（P2-R07）

- 保存问题、查询历史、所选资料、草稿、已保存成果；关面板 / 翻页不丢失。退出后恢复会话内容，未完成网络请求标为已中断，由用户重试，不静默重复付费请求。
- 长任务有阶段进度、取消、超时、重试；单个来源失败不清空其他成果，取消不撤回已经保存的笔记。
- 已保存结论、引用片段和允许保存的正文快照离线可读；缓存与用户保留内容区分，清缓存不能删除已保留证据。
- 新抓取版本不覆盖旧引用依据；展示抓取时间，网页失效时保留本地证据。
- “稍后研究”保存选区和问题，之后继续；研究笔记可主动加入复习，默认不加入。复习接入复用现有排期，不新造第二套系统。

## 4. 数据与工程实现要求

以下为建议领域结构，名称可按代码约定调整，关系和行为必须保留。实施前核对最新文件格式，不能假定仍是 format 6。

| 对象 | 最少保存的信息 |
| --- | --- |
| ResearchSession（研究会话） | ID、问题、触发来源、上下文范围、查询 / 对话历史、选中资料、草稿、任务状态、创建 / 更新时间 |
| SourceAnchor（触发位置） | PDF 文档 ID、页与矩形、原句及必要邻文；或卡片 ID、脑图 ID；不能只保存屏幕坐标 |
| ResearchSource（资料） | URL / 规范 URL、类型、标题、作者、日期、DOI / 视频 ID（如有）、读取状态、抓取时间、内容版本及快照引用 |
| Evidence（证据片段） | 来源及版本、原文片段、段落标识 / 页码 / 视频时间范围、获取方式；区分用户粘贴与自动获取 |
| ResearchNote（研究笔记） | 标题、正文、原问题、引用集合、用户 / AI / 摘录来源标识、创建与更新时间、可选复习关联 |
| NoteAttachment（笔记关联） | 同一研究笔记与 PDF 锚点、卡片 / 节点的关联；解除关联与删除笔记是不同操作 |

### 4.1 分层

- `mm_core`：纯 Dart 实体、编辑操作、查询、端口与关系约束；不得引入网络 SDK、Flutter 或平台插件。
- `mm_data`：学习集内研究数据、资源和内容快照的原子保存、迁移、恢复。大型正文与资源独立保存，编辑一个节点不反复重写所有全文。
- 外部搜索、网页提取、AI、字幕等用独立适配层实现核心端口，可增加专用包；原生安全存储、浏览器、OCR 等经 `mm_platform` 封装。选型后更新架构文档。
- 应用层在 `features/research/` 组合会话状态和界面，与工作区通过明确接口关联，不把请求流程塞进 PDF 组件或脑图画布。
- 网络与提取任务不得阻塞 UI；限制并发、内容大小、超时和重试，支持取消，正文按需加载，避免大图 / 大文档造成内存持续增长。

### 4.2 一致性、迁移与删除

- 新格式沿用逐级迁移、源版本备份、临时文件原子替换。旧高亮、卡片、图结构、图片、复习记录及到期时间保持不变。
- 旧笔记按纯文本兼容；来源类型应支持 PDF 摘录、外部图片、研究笔记，不能强制每张新卡都具有 PDF annotationId。
- 取消 / 撤销不留下半张卡片和失效引用；资源清理需要考虑共享引用及撤销窗口，不能删除仍被其他图、笔记或历史引用的图片 / 快照。
- 删除 PDF 或脑图节点默认解除该处关联，保留仍有用的研究笔记和证据；来源删除后标记不可定位，不能悄悄跳到错误页面。彻底删除研究笔记应明确处理全部关联。
- 复制到另一学习集时必须带齐允许迁移的笔记、引用与资源，或明确降为独立文本；不得留下跨学习集悬空 ID。
- Markdown / OPML 导出需保留研究笔记与可读出处；新增格式内容不能在旧导出中静默消失。

### 4.3 网络内容与隐私

- 用户能看到发往外部服务的上下文范围；不默认上传整本 PDF，不自动读取浏览器登录凭据。
- 网页与论文内容视为资料，不作为 AI 的操作指令；网页中的提示不能触发工具执行、读取本地文件或上传额外上下文。
- URL 获取校验协议、重定向和目标地址，阻止网页请求访问本机 / 内网资源；正文渲染清理脚本与危险链接，Markdown 图片也按同样边界处理。
- 深入自动研究要有请求数 / 耗时 / 费用上限与取消入口。具体上限随服务选型记录，不无限循环搜索。

## 6. 验收场景与质量门槛

各功能除表中验收项外，至少覆盖以下端到端场景：

1. 选中 PDF 一句话 → 查证 → 搜索真实资料 → 提取正文 → 人工选段与 AI 总结 → 修改结论 → 同时保存到原文与脑图 → 改任意一处，两处一致 → 重启仍可定位两种来源。
2. 从脑图节点发起“解释” → 明确未联网 → 保存 AI 解答；不伪造引用，默认不进入复习。
3. 请求期间切换 PDF、脑图、选区 → 结果仍属于原会话，保存目标不串位；新问题可独立研究。
4. 无 AI 配置、断网、搜索失败、正文提取失败、仅论文摘要、无字幕视频分别有真实状态和可行退路；离线可读已经保存的证据。
5. 关闭 / 重开 / 退出 / 重试 / 取消 / 重复保存 / 撤销重做均不丢草稿、不重复创建、不静默重复收费请求。
6. PDF 删除、节点删除、研究笔记解除关联、跨图复用、复制到另一学习集后，无悬空关联和资源误删。
7. 老学习集升级后原文定位、脑图、复习数量与排期保持；故障中断迁移可恢复。
8. 长文章、表格、代码、中英文混排、跨页选区、大脑图、窄窗口、浅深色、键盘和中文输入法均可用。
9. 网页含诱导 AI 执行操作的文字、脚本、恶意链接或内网跳转时，不改变授权范围或执行页面指令。

测试应分层：核心关系 / 编辑 / 引用与迁移用确定性测试；搜索和 AI 使用可控替身覆盖错误与取消；最终至少一次真实服务验证，不把替身测试写成平台已接通。复用现有性能基线，记录测试数据规模与测量结果。按仓库要求完成静态检查、相关测试和覆盖率门禁；涉及界面的功能需 Mac 真机验收，不能用编译通过代替。

每项完成后在本文登记状态、PR / commit、验证证据与剩余限制，并同步 [项目计划](project-plan.md)、[架构](architecture.md) 和 [真机验收](macos-acceptance.md)。设计令牌变化同步设计规范。

## 7. 给接手 agent 的执行说明

1. 先读本文、项目计划、架构与贡献指南，检查当前分支和未提交修改；不要覆盖其他任务的工作。
2. 按分配的 ID / 批次实施，检查依赖。未分配的后置功能不能顺手扩成一个大工程。
3. 开始前核实当前实现与本文基线差异，已完成的能力复用；能力或平台尚未验证时先做最小实测并记录结果。
4. 服务提供者、AI 凭据模式、OCR 引擎、嵌入网页方式尚待选型；优先隔离接口，不让一个平台失败阻塞手动阅读摘录。涉及用户费用、账号或新增外部服务的决定明确记录，不擅自订阅。
5. 首版交付不可省略来源追溯、统一笔记、恢复和失败状态来换取更多平台按钮。
6. 当前文档任务只整理需求；本次没有授权自动启动全部实现，也没有创建工期或版本承诺。

## 8. 接入参考与已知边界

以下为方案调研参考，实施时重新核对最新文档、权限与费用，不据此锁定供应商：

- [Mozilla Readability](https://github.com/mozilla/readability)：正文提取组件，Markdown 转换另行处理；提取结果不保证覆盖所有网页。
- [OpenAlex 检索](https://help.openalex.org/api/searching/)：结构化论文检索候选，检索命中不等于取得全文。
- [YouTube captions.download](https://developers.google.com/youtube/data/reference/rest/v3/captions/download)：官方接口要求调用者有编辑视频的权限，不能假设可下载任意公开视频字幕。
- B 站搜索、嵌入播放和字幕获取分别验证；本次未验证其稳定接口，不承诺所有视频可转录。
