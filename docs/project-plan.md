> 这份文档记录 MarginMind 从立项到现在的来龙去脉、已经完成的工作，以及接下来要做的事情，供安排后续任务时参考。
> 计划只列**事项、验收标准和先后顺序**，不估工时。每完成一项，请在这里打勾，并在“版本记录”里补一行。
>
> 最后更新：2026-10-26（体验审查之后）

---

## 1. 初衷

发起人是 **MarginNote 4 的付费用户**。MarginNote 的核心价值是“读 → 摘 → 图 → 复习”的学习闭环：在原文里划线，摘录变成卡片；卡片组成脑图；从卡片能一步回到原文出处；最后通过间隔重复把知识记牢。

我们希望用 **Flutter** 做一个**开源**的同类工具，目标是：

1. **把这个学习闭环做扎实**，不追求一开始就具备 MarginNote 的全部功能。
2. **像一个真正的 Mac 应用**，而不是“网页套壳”。早期设计稿被评价“太像 Web”，因此整体改为遵循 Apple Human Interface Guidelines（macOS 26 / Liquid Glass）：浮动玻璃侧栏、统一工具栏、系统字体与语义色、完整的菜单栏和快捷键、右键菜单、跟随系统外观与辅助功能设置。
3. **本地优先**：单机运行，数据保存在本机，每个学习集是一个可以整体备份的文件包，不依赖服务端。
4. **工程上可持续**：分层清晰（领域层是纯 Dart），编辑操作写成纯函数，测试不依赖界面，支持多语言（中文 / 英文）和浅色 / 深色主题。

立项时评估过的主要风险：PDF 交互（选字、坐标、高亮叠加）和大画布脑图的性能。目前前者已用 pdfrx（PDFium）跑通，后者仍需在第 4 节里继续优化。

### 2.3 当前能力一览

- **资料库**：新建 / 重命名 / 收藏 / 删除学习集；示例学习集；继续学习；待复习徽标；图标 / 列表视图、筛选、搜索、排序；拖入 PDF 新建学习集。
- **阅读**：导入 PDF（⌘O、侧栏 +、拖入窗口）；多文档标签页；原文 / 分栏 / 脑图三种布局；记住每份文档读到的页码；可以跨页选择文字。
- **标注**：默认是选择工具，选中文字后弹出浮动工具条（颜色点摘录到脑图、仅高亮、复制、添加笔记，E / H / ⌘C）；点击已有高亮弹出同样的工具条；切到高亮笔（⇧⌘H）后拖选即高亮并生成卡片；框选（⇧⌘R）区域生成带截图的图片卡片；记住上次使用的工具。
- **脑图**：所有卡片原地编辑（支持中文输入法）；XMind 快捷键（Enter / ⇧Enter / Tab / ⇧Tab / ⌘Enter / ⌫ / ⌘/ / ⌘↑↓ / ⌘0）；多选与批量操作；节点和子树的复制、剪切、粘贴（与缩进文本互转）；拖拽预览与边缘自动滚动；视图跟随与居中；自动布局与缓存；右键菜单；卡片一键回原文；大纲视图支持同样的编辑和快捷键；一个学习集可有多张脑图，同一张卡片可放进多张图；关联线和概要（可加标签，导出时保留）；卡片标签，侧栏按标签筛选。
- **复习**：摘录、笔记和图片卡片自动成为卡片；空格翻面、1–4 评分；可从答案回到原文；工作区里按当前脑图复习。
- **其他**：撤销 / 重做；侧栏搜索卡片；导出 Markdown / OPML；中英文；浅色 / 深色。

### 2.4 已知限制（v0.5）

- 复习排期是简化 SM-2，没有复习日志和统计；不能按标签或分支复习，也不能暂停某张卡片。
- 单窗口（资料库和学习集在同一窗口内切换）。
- 数据是 JSON 文件包，还没有用 SQLite。
- 没有 Developer ID 签名和公证。**这一项暂不安排**，为时尚早。

## 3. 上下文：技术与工程约定

### 3.1 技术栈与仓库结构

- Flutter **3.47.2**（`.fvmrc` 固定），Dart pub workspace，macOS 优先（部署目标 12.0）。
- 包与依赖方向（只允许向内依赖），详见 [architecture.md](architecture.md)：

```
apps/marginmind  →  mm_design / mm_platform / mm_pdf / mm_data / mm_layout  →  mm_core
```

| 包 | 职责 |
| --- | --- |
| `mm_core` | 领域层（纯 Dart）：实体、`StudySetEditor` 纯函数编辑、复习排期、导出、仓库端口 |
| `mm_data` | `FileLibraryStore`：学习集文件包 `<id>.mmset/studyset.json` + 按 SHA-1 去重的 PDF，原子写入 |
| `mm_pdf` | 基于 pdfrx 的 PDF 视图、选字、高亮叠加、定位 |
| `mm_layout` | 脑图树布局 |
| `mm_design` | 设计令牌、主题、macOS 风格组件（含右键菜单、HUD、Sheet 等） |
| `mm_platform` | 窗口、拖动、快捷键、系统外观 |
| `apps/marginmind` | 组合根：Riverpod、路由、菜单、功能界面、多语言 |

### 3.2 关键设计决定

- **内容不可变 + 纯函数编辑**：`StudySetContent` 不可变，所有修改都是 `StudySetEditor` 上的纯函数，仓库负责原子保存。撤销 / 重做靠保存快照实现，而且撤销时保留复习记录和阅读页码。
- **原文是锚点**：高亮同时保存 PDF 坐标和原文文字；卡片和高亮双向关联。
- **命令先进菜单**：新命令先在 `app_commands.dart` 定义（菜单栏 + 快捷键），工具栏只是快捷入口。
- **样式只来自令牌，文案只来自 ARB**。
- **未完成的功能不露出入口**：不放“即将推出”的按钮。

### 3.3 工作流程

- 分支开发 → 推送 → 开 PR（中文，包含“目标 / 改动 / 验证”三节）→ CI 通过后由项目所有者合并。
- 提交前：`dart format`（行宽 120）、`flutter analyze`、各包测试（见 [CONTRIBUTING.md](../CONTRIBUTING.md)）。
- 涉及交互的改动要在 **macOS 真机**上构建验证。目前通过远程 Mac 构建，并用桌面自动化截图检查。发布前按 [macos-acceptance.md](macos-acceptance.md) 逐项确认。
- 发布：推送 `v*` 标签触发 `Release` 工作流。重新签名时**必须保留 entitlements**，否则沙盒丢失、读不到已有数据（v0.3 验证时踩过的坑，工作流里已加检查）。

### 3.4 踩过的坑

- `Matrix4.getMaxScaleOnAxis()` 会把 z 轴也算进去（值恒为 1），读不出脑图的缩放比例；应使用 `mapScale()`（`storage[0]`）。
- Riverpod 3 中没有监听者的 Provider 会暂停；测试里先 `listen` 再读 `.future`。
- 写入后流事件稍后才到，控制器里以“最近一次写入或流事件”作为当前内容。
- 自动化拖拽太快（移动事件太少）时，Flutter 的 `Draggable` 不会触发；真机手动验证不受影响。
- 桌面自动化注入的修饰键（⌘、⇧）Flutter 收不到，带修饰键的快捷键和 ⌘ 点击只能靠组件测试或人工验证；菜单命令可以用自动化点菜单项验证。
- 脑图画布在布局时会调整 `TransformationController`（保持根节点位置），监听它的组件不能直接 `setState`，要推迟到帧结束（见缩放比例标签）。
- `InteractiveViewer` 把每个鼠标滚轮事件都当成缩放（没有选项改成平移），而且它不经过 `pointerSignalResolver`，外层拦不住。脑图因此关掉它的 `scaleEnabled`，在外层 `Listener` 里自己处理：滚轮平移，⌘ / Ctrl + 滚轮、触控板捏合（`PointerPanZoom` 的 `scale`）和 `PointerScaleEvent` 缩放；触控板双指滑动仍由它平移（GUL-503）。
- 用 `TextPainter` 预先测量文字时，要合并 `DefaultTextStyle`：macOS 的 Material 字体排印给默认样式加了系统字体和 `letterSpacing`，`Text` 会继承而裸的令牌样式没有，测出来偏窄，真机上英文标题会折行、最后一个字被挤掉（v0.5 验收时修复，见 `MindMapRenderCache`）。测试字体等宽，测不出这类差异。

## 4. 开发计划

编号用于安排任务，例如 `E-03`。每项都写了验收标准；✅ 表示已完成。

### 4.1 脑图编辑：参照 XMind 重做（第一优先）

**目标**：编辑脑图时手不离键盘，不出现对话框。

| 编号 | 事项 | 验收标准 |
| --- | --- | --- |
| ✅ E-01 | **原地编辑**：节点直接变成文本框，宽度随文字增长，布局和连线实时跟随 | 编辑时节点就地变宽，相邻节点平滑让位；不再弹出重命名对话框 |
| ✅ E-02 | **进入 / 退出编辑**：双击、F2、空格进入；选中后直接打字，以输入内容替换原标题；Enter 确认、Esc 取消、点别处确认 | 行为与 XMind 一致；Esc 恢复原文字 |
| ✅ E-03 | **中文输入法**：输入法组合期间（拼音未上屏）Enter 只用来选字 | 中文输入法下 Enter 不会提前提交；用测试覆盖 |
| ✅ E-04 | **XMind 快捷键**：Enter 在后面加兄弟节点、⇧Enter 在前面加兄弟节点、Tab 加子节点、⇧Tab 提升一级、⌘Enter 插入父节点、⌫ 删除、⌘/ 折叠、⌘↑ / ⌘↓ 排序、⌘0 适应窗口 | 新建的节点直接进入编辑；在菜单栏“脑图”中列出这些快捷键 |
| ✅ E-05 | **空节点处理**：新建后没输入内容就按 Esc，等于没有创建 | 不会留下“新主题”之类的残留节点；撤销记录里也没有这一步 |
| ✅ E-06 | **摘录与笔记**：摘录卡片的标题、笔记正文也原地编辑；笔记用 ⇧Enter 换行 | 所有类型的卡片都不再需要对话框 |
| ✅ E-07 | **撤销粒度**：一次编辑算一步撤销；编辑文字时 ⌘Z 只撤销文字 | 连续输入后按 ⌘Z，不会把整个节点撤销掉 |
| ✅ E-08 | **多选**：⇧ / ⌘ 点击、在空白处拖出选框；多个节点可以一起删除、移动、改色 | 选中的节点都有清楚的标记；批量操作只算一步撤销 |
| ✅ E-09 | **复制、剪切、粘贴**：⌘C / ⌘X / ⌘V 处理节点和子树；可作为缩进大纲文本粘贴到其他应用；从其他应用粘贴多行文本时，按缩进生成节点 | 在 MarginMind 与备忘录 / XMind 之间来回粘贴，结构保持不变 |
| ✅ E-10 | **拖拽体验**：拖动时显示插入位置的预览线；拖到边缘时画布自动滚动 | 拖到画布外侧时画布跟着滚动；落点和预览一致 |
| ✅ E-11 | **视图跟随**：选中或新建的节点自动滚到可见区域；“居中到当前节点” | 用键盘连续加节点时，编辑中的节点始终在视野内 |
| ✅ E-12 | **性能**：缓存布局和文字测量结果，只重绘变化的部分，平移缩放时不重新计算布局 | 500 个节点时编辑、拖拽、缩放都流畅（目标 60fps）；有性能基准测试 |
| ✅ E-13 | **大纲视图同步**：大纲支持同样的原地编辑和快捷键 | 只用键盘就能在大纲里写出一棵多层的树 |

### 4.4 学习与体验（第三优先）

### 5.1 v0.6 的安排

现状：`ReviewState` 只保存每张卡片最近一次的排期（间隔、难度系数、连续次数、遗忘次数、上次复习时间），没有逐次的复习日志，也没有暂停标记。L-01 ～ L-03 都要改数据，所以像 v0.5 一样，先做**一次**格式升级，再分头做功能。

| 顺序 | 事项 | 内容与验收要点 |
| --- | --- | --- |
| 1 | **数据格式 5 与迁移** | 一次加齐：每次评分追加一条复习日志（卡片、时间、评分、评分前后的间隔）；FSRS 需要的记忆状态；卡片的暂停标记。沿用 4→5 原子迁移和按源版本备份；旧的 `ReviewState` 原样保留，日志从空开始。迁移回归测试用 format 4 的固定数据集。 |
| 2 | **L-01 FSRS 排期** | 依赖 1。`ReviewScheduler` 换成 FSRS，评分界面不变。旧卡片从 SM-2 状态（间隔、难度系数、遗忘次数）推出初始记忆状态，到期时间保持不变，所以迁移当天不会多出到期卡片。用固定数据集回归：迁移前后每天的到期数量曲线没有尖峰。 |
| 3 | **L-02 复习统计** | 依赖 1，与 4 并行。统计只读复习日志：每天复习量、记住的比例、未来 30 天每天的到期数量。入口放在资料库和学习集的“学习”分组；没有日志时不显示入口。 |
| 4 | **L-03 复习范围** | 依赖 1，与 3 并行。按标签复习（C-05）、按脑图分支复习（C-03）；节点菜单可以暂停 / 恢复一张卡片，暂停的卡片不进复习队列也不计入待复习数。 |
| 5 | **v0.6 验收与发布** | 按 [macos-acceptance.md](macos-acceptance.md) 补 L 项，重点验证 v0.5 数据迁移后到期数量不变，打 `v0.6.0` 标签。 |
