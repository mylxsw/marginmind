# 大纲切换节点卡顿排查（2026-10-28）

原因有两处：

- `_OutlineRow` 用带双击识别的 `MMInteractive.onTapDown` 选择节点。快速点击时，选中回调要等双击识别结束才执行；50 节点也有约 332 ms 的响应等待。
- 每次选中变化都递归调用 `childrenOf`、`card`、`annotation` 并重新创建所有行。这些查询逐个扫描列表，整棵树的查询量随节点数量平方增长。500 节点的回归用例中，仅按一次向下键就触发 1001 次节点/卡片查询，且所有行重新构建。

修复让鼠标主键按下直接选择，记录修饰键并跳过后续手势回调的重复选择；双击继续进入编辑或定位原文。触屏仍走手势识别，滑动列表不会直接选择。大纲在内容快照或活动脑图变化时建立索引；单纯切换选择复用未变化的行，编辑、内容更新、主题与语言变化会刷新对应显示。

## 原生测量

macOS 27.0.1、Mac15,10、36 GiB 内存，Flutter 3.47.6，Profile 模式。使用同一份 `apps/marginmind/tool/outline_performance.dart` 驱动真实 `MapPane` / `WorkspaceController` / `OutlineView`，数据与偏好保存在内存，不读写用户资料库。

表中规模为卡片节点数，另有一个虚拟根。每个规模交替选择前两行 30 次；`selection` 直接调用控制器，覆盖与方向键相同的选择更新路径；`mouse` 向 Flutter 手势系统注入主键按下与抬起事件，经过实际双击识别。操作间隔 350 ms，避免连续操作被合并成双击。修改前的大纲源文件 Git blob 为 `0f0e8db`，其余代码为当时工作区已有内容。

数值为第 95 百分位（95% 的样本不超过此值），单位 ms：

| 节点数 | 方式 | 响应：修复前 → 后 | UI 帧构建：修复前 → 后 | 超 16.67 ms 帧：修复前 → 后 |
| --- | --- | --- | --- | --- |
| 50 | 直接选择 | 17.83 → 15.43 | 4.35 → 3.55 | 0 → 0 |
| 50 | 鼠标点击 | 332.28 → 27.16 | 4.31 → 3.36 | 0 → 0 |
| 500 | 直接选择 | 36.31 → 19.34 | 20.86 → 12.46 | 22 → 0 |
| 500 | 鼠标点击 | 355.21 → 30.65 | 31.59 → 12.05 | 11 → 0 |
| 2000 | 直接选择 | 139.88 → 37.79 | 133.67 → 25.19 | 30 → 26 |
| 2000 | 鼠标点击 | 459.98 → 34.57 | 137.36 → 24.49 | 30 → 30 |

“响应”从调用选择/注入鼠标按下计时，到选择状态已改变并等待后续 UI 帧结束；鼠标模拟包含 8 ms 后抬起，可能多等待一帧。它不是显示器呈现延迟，也不是人工鼠标操作测量。帧构建和绘制耗时来自引擎 `FrameTiming`；超预算帧指两者任一超过 16.67 ms。鼠标按压反馈增加了修复后的帧数，完整汇总见 [修改前](before-profile.json) / [修改后](after-profile.json)。

500 节点场景在本次采样中已无超预算帧；2000 节点仍有约 25 ms 的帧构建开销。当前保留全量行挂载以支持可变行高和任意选中节点的自动滚动，大规模场景后续还可改为仅挂载可见行。本次没有把该剩余开销标记为已消除。

## 长按方向键与工具栏焦点（2026-10-28）

后续补测发现另一处独立问题：大纲和画布的按键处理都只接收 `KeyDownEvent`，长按产生的 `KeyRepeatEvent` 被返回为 `ignored`。Flutter 的 macOS 默认方向键快捷键会将这些事件解释为 `DirectionalFocusIntent`，于是焦点离开脑图。回归测试精确复现了：从大纲的 `c4` 按上键，第一次选择 `c6`，第一次重复事件就把焦点交给 `Source Only（⌘1）`（中文“只看原文”）按钮。按钮显示的是键盘焦点边框，工作区布局没有切换。

修复接收导航键的重复事件，并在首尾、叶节点等无法继续移动时也消费事件，避免焦点落到工具栏。编辑字段仍先接收自己的按键；增删、折叠、重排等命令只在第一次按下时执行，重复事件被消费，不连续修改内容。

新增三组共用场景：大纲四个方向的连续按键与边界；画布连续进入子节点和叶节点边界；折叠命令只执行一次以及编辑字段保留焦点。前两组在修复前均失败，修复后通过。原生入口复用同一组场景并使用内存资料库：

```bash
cd apps/marginmind
flutter test --no-pub test/map_keyboard_test.dart test/card_edit_test.dart test/outline_performance_test.dart
flutter drive --no-pub -d macos --profile --driver=test_driver/integration_test.dart --target=integration_test/map_key_repeat_test.dart
```

本次长按修复的应用全量测试：599 项通过、8 项跳过；相关键盘/编辑/大纲测试 26 项通过；静态检查无问题。当前用户使用的应用进程未替换，资料库未改动。

macOS Profile 原生验证的三组键盘场景全部通过，`flutter drive` 返回 0；其结果通过 VM Service 驱动收集。原生场景显式指定物理按键，并关闭测试框架逐项强制开启的语义树（这些场景不做无障碍断言），避免系统延迟启用无障碍支持造成测试句柄计数误报。常规 Widget 测试仍使用默认语义树检查。原生验证使用注入的按下/重复/抬起事件，未将其记为实际硬件键盘长按验收。
