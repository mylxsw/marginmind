## 内容与设备状态

文件格式 11 的 `StudySetContent` 继续作为本地模型。同步投影把集合按稳定 ID 编码为字典；
节点使用 `(mapId, cardId)`，译文缓存使用 `(documentId, targetLang)`，排期使用 `cardId`。
笔记章节和块分别保存 `items` 与 `order`，正文修改不因数组位置变化而寻址到另一条记录。
未知集合、重复身份与字典键/实体 ID 不一致均拒绝解析。

`sharedContent` 排除阅读位置、最近阅读时间、折叠状态、复习三组数据、助手执行回执及本机对照配置。
`materializeShared` 恢复本机阅读与折叠状态、保留独立管理的复习数据。复习、生词和译文使用下述专用协议；
当前投影里的 `translationCaches` 仅是旧格式缓存。
日志已经分开保存 `sets/<id>`、`reading/<id>/<device>`、`reviews/<id>`、`words/<identity>`、本机 `vocabulary` 索引和
`translated/<set>/<document>/<language>`（旧 `translations/` 聚合冻结保留）。复习流使用共同基线与追加事件；
译文流保存段落及 origin，不保存任务 job 状态。不能仅凭数据分流就宣称领域合并已完成。

## 三方合并

- 一端未变时接收另一端；相同变化只保留一份；不同字段递归合并。
- 同字段不同值、删除与编辑并发、相同 ID 的不同新增记录产生显式冲突。
- `updatedAt` 只合并修改时间，不决定正文胜负，也不用于判断因果；`organizedAt` 是资料收集基线，
  并发不同基线必须保留冲突，不能按较晚时间自动选择。
- 有序笔记块的独立插入合并为稳定顺序；两端相互矛盾的顺序保留为冲突。
- 脑图同排序值使用稳定卡片 ID 作为第二排序键。合并后校验环、父节点、图/卡片/文档引用、
  关系线、概要（含概要节点的子节点）、书签、研究笔记关联及文本标注 revision；
  还校验批注的文档/节点、笔记中指向摘录/自有内容的活引用和章节交叉引用。

`ContentMergeResult.content` 是预览。字段冲突保留基线值，同时返回包含双方候选的 `SyncConflict`；
结构校验失败则 `content == null`。调用者必须先保存冲突及输入版本，不能将预览当成无冲突的提交。
纯快照合并函数只处理一个输入单元；学习集仓库现在按单次仓库提交重放原子修改，让无关事务继续同步。
工作区显式编辑会话已把跨多次仓库写入组合成一个共享内容事务；其他编辑入口仍需逐一接入并验收。
没有共同祖先、或有多个最大共同祖先时，调用者必须保留分支，不能随意选一个基线。

## 安全撤销

每次本地操作记录前后字段差异。撤销与重做在仓库最新快照上校验预期值，然后一次性应用全部差异；
任何字段或引用约束不满足都不发布候选内容。事务只组合本地操作，不把操作间到达的远端变更纳入历史。
连续修改同一字段会合并，避免每次按键都永久保存一个完整正文副本。
校验容忍当前数据或原操作目标中已有的旧引用错误，但不能因后来加入的内容制造新错误。
解码不运行旧文件的概要自动修复，避免合并/撤销悄悄制造新的卡片。

阅读与复习不进入撤销；普通修改时间不是撤销前提。笔记 `organizedAt` 决定新材料收集范围，
必须参与条件修改及撤销；`updatedAt` 仅在整条笔记仍匹配操作观察到的版本时恢复，否则保留后续写入的时间。撤销新建父节点时，如果它被后来新增的节点引用，
会拒绝该步，以免制造孤立节点。既有菜单和历史工具栏通过 `UndoneNotice.conflict` 显示本地化提示。
工作区还监听共享历史的冲突事件，覆盖忽略返回 notice 的 HUD 和原生菜单入口。
取消事务遇到冲突时，保留已提交内容与条件历史、结束事务并提示，避免编辑状态关闭后历史永久锁住。

## 提交与日志

新提交使用协议候选版本 2，尚未发布为长期兼容承诺；读入仍识别早期版本 1。提交包含：

```
protocol, id, libraryId, scope, deviceId, sequence, parents, deleted, payload, pending?, resolves?, requires?
```

`id` 是提交体的规范编码 SHA-256；v2 对对象排序、区分 JSON 类型，并把有限数值编码为 IEEE-754
字节（零统一为正零，拒绝超过安全整数范围的数值），避开 Dart VM/JavaScript 对 1/1.0 和指数文本的差别。
字符串不能冒充数值，数组不能冒充对象。`parents` 排序并拒绝重复；读入重新校验摘要。
删除提交只能携带空 payload。账号密码、token、系统密钥不属于此结构。
`SyncGraph` 拒绝缺失父提交、跨资料库/数据域父引用，以及同设备序号分叉。比较版本使用祖先关系，
时间戳不参与版本胜负。多个共同祖先显式返回集合，避免隐藏 criss-cross 分支。

日志按 `SHA256([libraryId, scope])` 隔离，存储在指定根目录下的 `.foliarc-sync/`。
每条提交先写同目录临时文件、flush、rename；未完成的临时文件不属于已提交数据。
重启读取全部已提交文件并校验因果图，损坏数据报错，不能静默覆盖或当作空资料库。
`pending()` 返回未确认的已提交版本；`acknowledge()` 只保存交付确认，不删除合并所需的历史。
调用者必须在云端确认持久化后确认交付，不能在 iCloud 本机暂存成功后确认。
新的传输调用提供 target 与 connectionRevision；历史无 target 的交付记录仍保留，仅供旧本地调用，不能继承为另一服务的交付确认。

当前日志采用单实例串行所有权；原生多进程、多实例写入不在本批承诺范围。
文件 flush + rename 覆盖进程中断恢复，不把它宣传成所有文件系统的掉电事务保证。
原生端仍要求一个资料库由同一 ledger 实例管理；应用启动时把它同时传给学习集与生词仓库，
译文仓库由学习集仓库传递该实例。并发原生进程写入尚不支持。

### 真实仓库提交与恢复

`.foliarc-sync/identity.json` 固定资料库及设备身份；缺失身份但已有日志时拒绝降级为普通本地模式。
身份不匹配会停止写入，不能把另一账号或资料库的队列接过来。服务绑定与交付确认按服务/账号/位置/资料库隔离；设置入口与账号生命周期见后续章节。

`.foliarc-sync/local/<hash>.json` 是本机事务事实，包含顺序、前驱、多个数据域的本地完整快照及
新生成的共享提交。**这些日志文件不能上传**；发送端只读取 `pending()` 返回的共享提交。
无需另写 outbox；本地状态和待发送版本要么一起存在，要么都未提交。仅本机字段变化可以更新本地快照，
不产生共享内容提交。`expected` 版本前提与领域校验在同一队列内执行，过期候选不允许覆盖当前版本。

原生端以 flush + rename 为提交点；Web 把记录与 `.head` 比较标记放在同一个 IndexedDB 事务内，
防止旧标签页在过期版本上另开分支。事务提交之后的 `.mmset`、生词 JSON、译文 JSONL 写入失败，
不会把已经提交的操作误报为失败；错误保存在 `projectionErrors`，读取和重启使用日志中的数据。
学习集和生词在加载时重建投影；译文读取日志，后续写入或整理时重建文件。

创建、元信息、内容与删除都已改成提交后发布内存和通知。文档包先准备不可变附件，再提交元数据；
提交后的投影失败不会回滚已经被引用的附件。删除学习集时，内容、本设备阅读、复习及已知译文墓碑同事务记录，
保留附件供后续恢复；删除文档也同步记录相关译文墓碑。子数据范围在 ledger 提交队列内确定，
覆盖排队期间刚创建的译文，不能先取快照再异步删除。译文写入在同一队列中再次检查文档生命周期，
拒绝迟到写入复活已删除内容。普通本地模式仍按既有策略删除文件包。

原有资料库首次进入日志模式会建立学习集及已有译文基线；生词首次加载/保存时建立基线。
初始化中的可重试投影/译文基线错误可查询，产品开启流程必须展示并处理这些错误，不能假装全部初始化成功。
当前保留所有本地历史；各领域远端应用与事件去重见后续章节，历史压缩和规模验收仍未完成。

### 远端接收与学习集应用

本机日志新记录使用版本 3，仍能重放版本 1、2；不支持新版本的旧客户端拒绝读取。
版本 3 增加本机恢复通知及确认记录，不进入待上传列表。版本 4 使用新的跨运行时摘要，
旧 v1/v2/v3 本机记录继续按旧算法校验，旧提交 ID 和父链不改写；后继可使用新协议。
接收记录保留不可变远端提交，允许乱序到达，不把“收到”当成“应用”。随后根据完整祖先关系计算候选，
学习集写队列中的提交再校验预期本地 revision；若已经变化，就从日志中的最新快照重新合并。
成功后再更新资料库内存并通知 `watch`，投影失败保持已提交结果，重启可恢复。

快进直接采用已有远端版本，不制造回声上传；并发独立修改生成引用双方父版本的新提交。
待发送列表只包含本机新生成的版本。处理候选时先尝试后代，再处理祖先，避免已收到合并结果时
仍为旧父版本制造交叉合并；坏的或缺少祖先的后代也不能隐藏可应用的祖先。

缺失祖先、无共同祖先、多个共同祖先、设备身份分叉、删除/编辑、字段或结构冲突均保留输入。
诊断跟随日志持久化；重复输入不重复生成诊断，已纳入成功结果的诊断在同一提交中清除。
未知提交若使用本机设备身份则拒绝接收；其他设备的异常分支保留诊断，不阻止在已接受谱系上继续本机编辑。
阅读位置、复习和本机显示状态不被内容应用覆盖；文档 revision 改变后不沿用旧阅读锚点。
远端文档、图片及研究快照引用必须是包内相对路径；资源解析也拒绝路径穿越及跨平台绝对路径。

`canApply` 仍可供外部调度器暂缓应用；仓库还会检查实际编辑会话及实体保护租约，不能由调用方省略回调绕开。
**此 API 仍不是完整同步引擎**：学习集仓库应用 `sets/`、`reviews/`、`folders/` 和独立设备 `reading/`；
生词仓库应用 `words/`，由共享 ledger 的 `FileSyncReceiver` 分发；资料库接收并应用 `translated/` 译文流。
资源 manifest/下载/校验门禁已接入，详见第十六批及后续资源入口章节。

### 资料库文件夹与归属

文件夹以 `folders/<id>` 独立保存 `{id, name}`。空设备没有文件夹根提交，可以直接接收已有文件夹；
不同文件夹的创建/改名互不阻塞。不能把每台设备自行建立的空 `library` 快照误认为共同历史。
旧 `library` 流不再随文件夹修改产生共享后继；它的本机快照仍保存完整文件夹索引，
和对应文件夹版本在同一个 ledger 记录中提交。旧本机索引在加载时建立一次 per-folder 基线，
不重写旧提交及父引用。早期仅有 `library` 共享快照的远端分支仍未自动迁移，不能把这种兼容读取
宣传成旧候选完整图迁移；服务开启前仍需迁移或明确门禁。

接收沿用因果图/事务重放：名称冲突保留双方候选，显式选择携带所见 revision；其他文件夹继续处理。
名字、身份、字段和祖先均校验，不接收额外私有字段或文件夹外部依赖。无共同祖先、多基线、
删除对改名仍保留分支并显示说明；并发选择已在第二十二批接入事务组确认。

删除文件夹不删除学习集，也不批量改写学习集原始 `folderId`。摘要在所指文件夹尚未到达或已删除时
显示“未分类”；原始归属保留，乱序到达后可以恢复显示。明确移动才修改学习集的共享元信息，
并校验观察到的原始归属和目标是否存在；即使不同未到达文件夹都显示“未分类”，也不能绕过过期校验。文件夹登记队列先于学习集写队列，避免验证后目标立刻被本机删除。
这是可容忍乱序的归属引用，不是文件夹与所有学习集之间的分布式原子事务。

管理入口在可选组织端口可用时显示，本地模式也可使用，不因此开启同步日志。删除前说明学习集会保留。
名称输入保留打开时的版本；收到远端更新不替换输入，过期保存拒绝并保留文字。
冲突只展示当前/候选名称，不让用户按摘要 ID 作选择。文件投影故障可重试，重启以日志重建索引。
活动文件夹被删除时切到“未分类”并保留搜索条件。此面板不是已删除学习集的全局恢复中心。

### 原子仓库事务与可传播冲突

学习集接收现在从完整因果历史重放单次仓库提交：单父提交代表一次编辑，其前提来自实际观察到的
父快照；多父提交是整合检查点，不当作第二次编辑。依赖先后确定后，以提交 ID 稳定排序并逐事务
校验字段与结构。一项修改有冲突时，整项暂不应用，后续只改其他字段的事务仍可应用。
例如两个合法脑图移动合并后会成环，则保留一个有效显示候选，另一个移动及同次写入的关联修改
一起进入待处理状态；后续学习集标题修改继续同步。这里的显示候选不是自动判定哪方胜出。

共享提交的可选 `pending` 保存未解决事务 ID；完整候选及其原始前提保留在不可变祖先中。
收到整合提交但缺少父版本时继续等待。新设备取得祖先后可以重建同一显示内容及冲突候选；
普通本地编辑必须继承待处理列表，不能借一次新编辑把旧冲突抹掉。
接收端在每个整合检查点自己的因果上下文内校验重放内容和待处理列表，拒绝省略冲突的检查点。
候选协议仍未发布；旧实现会因不认识新增字段拒绝这些提交，而非静默丢弃冲突状态。

`syncConflicts(id)` 查询事务候选；`resolveSyncConflict` 要求明确的本地 revision 和选择。
选择对方修改时仅替换该事务实际修改的路径，保留后来的无关修改；整个候选仍须通过结构校验。
选择保留当前内容也生成带 `resolves` 的因果提交。版本过期、结构无效或落盘失败时不发布结果。
尚有待处理事务时不能直接删除学习集，以免删除隐含解决冲突；清理选择后正常因果删除继续可用。
`ledger.issues()` 仍表示未应用分支的诊断，已经整合的未决事务由当前提交的 `pending` 表示，
类型化状态和学习集面板同时展示两者，不能把 `issues` 为空解释为没有冲突。

当前边界仍需完成：剩余输入保护、混合分支的更细粒度暂缓、资料库级异常分支恢复入口。
两端并发作出冲突选择现保存为可传播的 pending 事务组，第二十二批补齐再次确认。
无共同祖先/多个最大共同祖先仍保留分支。涉及旧删除后复活的复杂历史
不自动猜基线。重放目前保留完整历史并重复验证检查点，尚未完成增量缓存、压缩及规模验收；
不能直接据此开启用户后台同步。

### 工作区编辑会话与本地草稿

`ContentEditRepository` 是可选端口，不改变普通仓库的 update 约定。工作区最外层 begin/commit/abort
对接真实仓库边界：每次更新仍将完整本机快照写入同一 ledger，但 `draft` 期间保持原共享提交不变；
结束时才从最终内容生成一个共享提交。创建节点/概要后输入标题因此不再发布中间半成品。
成功取消并恢复原内容时没有新的共享内容提交。提交失败保留会话供重试；取消的反向写入已成功后，
即使最终发布失败，重试也不会再次应用反向修改。跨引用窗口沿用既有的同学习集共享编辑历史。

草稿是本机记录标记，不能上传。本机 pending 查询暂缓该学习集及其 reading/reviews/translations/translated
记录；不能把 .foliarc-sync/local 当作传输目录。重启时从最后保存的草稿恢复并封存一个内容事务，
`recoveredEditingDrafts` 暴露尚未确认恢复的学习集 ID，学习集面板提供持久确认。其他领域的临时记录、依赖顺序
与取消后收敛仍需在各领域处理器中完善，不能据此启用后台传输或宣称跨领域原子发布。

内联卡片、关系线和概要输入持有按稳定实体路径的租约，包含已有的关联卡片/概要/批注/标注。
开始输入前等待已经在途的仓库写入，再读取最新快照；之后触及这些实体或删除学习集的远端版本
暂缓，无关实体/元信息可应用。接收规划后在 ledger 队列中再次检查租约，避免检查与提交之间新开编辑。
创建类编辑的整个复合事务暂缓该学习集应用；结束或取消后对已持久接收的数据重新合并。
释放租约后的重试失败不会把已保存的本机编辑误报为失败；`editSyncErrors` 保留可查询错误，候选仍在日志。

卡片详情的标题/正文、研究笔记标题/正文、学习笔记标题/章节/Cornell 字段/文本块也已接入。
共享 `ContentInput` 在屏障后从仓库读最新内容，不依赖上一帧 widget 快照；活引用块还保护实际引用的
卡片/批注/研究笔记。先保护块再读取最新引用并获取来源保护，避免在途写入改变来源 ID 后保护旧对象。
保存失败保留输入和保护供重试；保存期间禁止再次提交和格式修改。销毁控件时，已开始的保存完成后才
解除保护；卡片详情保留既有关闭保存行为。尚未提交的学习笔记/研究输入关闭时仍按原行为取消，不宣称
键盘缓冲已持久化为恢复草稿。无同步端口的仓库保持原有即时编辑体验。

这仍不是全部输入控件的完整协调：独立 PDF 边注、标签/元信息弹层等入口还需审计；
一个远端快照同时含受保护修改与后续无关事务时，仍可能暂缓到当前输入结束。
当前租约是实体级保护，不应宣称已实现任意字段、任意远端分支的局部应用。

### 同步状态、冲突选择与恢复确认

`ContentSyncRepository` 是 core 的可选端口，UI 只依赖类型化状态和操作，不读取私有日志 JSON。
工作区侧栏和更多菜单在日志模式下提供“同步与恢复”；普通本地仓库不增加入口。
面板处理保存状态和内容冲突，并指向设置中的服务传输状态；待发送/无冲突均不表示云端交付成功。
状态订阅同时观察持久提交、输入租约、投影错误和交付确认；关闭界面后取消订阅。

当前提交的每个 pending 事务显示原始修改的全部字段，包括同次修改中的无冲突部分，
以当前内容和候选内容对照。关系引用转换成实体名称，章节/块展示文字，不要求用户解读哈希或 JSON。
候选结构不合法时禁用应用；输入期间禁用选择。保留/应用均带展示时的 revision，过期操作提示重新检查，
不能把新修改覆盖掉。尚未应用的分支以缺失历史、基线不明确、并发选择等独立提示保留。

重启封存草稿时，恢复通知与内容发布写入同一个本机事务；通知在再次重启后仍存在。
“已检查恢复内容”仅确认对应恢复标识，磁盘写入失败或新恢复替换了旧标识时不消除通知。
确认不产生共享编辑，不清除内容或历史。重试从日志修复学习集/译文/资料库文件，恢复失败的草稿封存，
再尝试已接收分支；投影失败不重复业务修改。保存成功但释放保护后协调失败也在面板显示。

该面板是学习集级入口，尚未覆盖无法打开或已删除集合的资料库级恢复中心；无基线、多基线、
删除对编辑仍保留分支和说明原因，尚无进一步人工整理流程；并发选择现可在面板确认事务组。复杂结构/资源差异只提供文字摘要，
未实现图形差异预览。账号连接设置、前台同步调度和资源可用性已接入，默认仍不启用后台传输。

### 候选协议的跨运行时修正

本轮复核发现早期候选直接哈希 JSON，会因原生的 `1.0` 与 JavaScript 的 `1` 编码不同而拒绝同一提交。
协议 v2 改为上述带类型的规范摘要；内容比较也按 JSON 数值语义处理，不把整数/浮点编码差别当作编辑冲突。
固定摘要样例及原生生成的评分提交/排期样例同时在 VM 和 Chrome 校验与重放。
旧 v1 提交及 v1 冲突对象保留其旧算法和身份，新冲突对象版本为 2。本机 v3→v4 的恢复/后继写入有测试。
独立 FileSyncJournal 的目录名继续使用旧的字符串身份摘要，以免改算法后丢失已有目录。

早期 v1 候选没有可承诺的跨运行时数字格式；现在支持在原运行时继续恢复它们，**不宣称已修复旧 v1 的
跨运行时传输**。正式开启传输前，仍需把既有候选历史按验证后的完整图迁移或给出明确兼容门禁；
不得悄悄重算旧 ID、丢弃候选或清空历史。目前没有用户后台同步开启，也没有发布长期协议。

### 复习共同基线与评分事件

`reviews/<set>` 的 `review-events` v1 保存不可变共同基线、基线摘要，以及按评分 ID 保存的事件。
基线包含既有排期、记忆参数和原始日志；旧日志可能不完整，不把它们假装成可重新计算的全量事件。
沿用原文件读取器的确定性迁移，补齐缺失的旧记忆参数但不改变 due；已有日志仍可没有算法描述。
旧候选 reviews 快照通过一个明确的单父后继升级，新导入的本地资料直接建立基线。
尚未收到共同基线的设备可以编辑内容，但不能自行新建空复习历史后评分。

新评分记录保存 `foliarc-fsrs5` 算法版本 1、参数格式版本 1，以及完整权重、目标保留率、最大间隔。
评分事件还保存产生设备和已观察事件的因果前沿。调度/舍入/学习步骤的语义变化必须新增算法版本；
仅更换参数值也会保存在对应事件中，不能用接收设备的当前设置重新解释旧评分。
接收时校验作者、祖先、不可变旧事件、基线一致性、无环因果图；未知算法/参数版本保留诊断，不覆盖排期。
多父提交仅整合已存在事件，不能在检查点里凭空增添评分。无共同祖先或多个最大共同祖先仍保留分支。

重放先满足因果关系，再按原始 UTC 评分时间及事件 ID 排序独立事件；每选一个事件后重新计算可执行项。
设备时钟回拨不会让调度所用 lastReviewedAt 倒退；原始评分时间及当时观察的 intervalBefore/After 不改写。
每次重放都从共同基线计算，因此同一组事件在所有设备得到相同排期，重复接收不重复计分。
这项排序不用于正文冲突选赢家。评分历史不会复活卡片或学习集，已删除卡片的历史仍被保留。

`SyncCommit.requires` 显式记录跨域版本依赖；本地 `requireScopes` 在 ledger 原子提交队列内绑定，
可指向同一笔写入中新建/修改的内容提交。评分事件、本机排期和待发记录同一次落盘；投影失败只需修复文件。
接收复习版本先等待所引用内容进入已接受的因果历史，缺失内容/历史时持久等待，绝不以时间戳覆盖。
“已接受”包括携带 pending 的内容整合提交，并不替用户解决正文冲突；评分是独立历史，可能暂时对应
尚未显示或已删除的卡片，不因此创建该卡片。学习集删除仍由内容域拥有，迟到评分不能复活它。
不支持的反向或其他内容域依赖保留分支，不能跳过未知依赖直接发布。

复习应用与本机评分走同一个学习集写队列；提交前同时检查内容与复习 revision，版本变化后重读重放。
落盘后更新真实仓库内存及 watch；同步面板也显示复习流的未应用诊断。
当前 receiveSync/reconcileSync 的返回计划列表仍为内容域，复习问题通过类型化状态端口展示。
显式复合编辑期间暂缓复习接收，并拒绝新评分，避免对最终取消的临时卡片发布评分；提交/取消后自动重算。
普通实体输入租约不阻止独立排期更新，因为复习不改动输入正文或撤销历史。
保存失败时评分界面保留已翻开的当前卡片及队列，提示重试；保存中禁用评分并防止重复按键。
缺失基线或未结束编辑显示对应说明，旧会话的异步完成不会推进新会话。

尚未提供任意重置排期/覆盖记忆参数的共享事件，日志模式下不允许直接篡改排期或删改已记录评分。
默认本地模式仍保留原操作。独立历史、未知版本、删除后复活的人工整理流程仍需完善。
复习与阅读对内容的依赖和编辑取消场景已有独立处理；这不代表 translations 等其余领域已完成原子发布。
历史校验和事件重放尚无增量缓存/压缩，未做大型资料库性能承诺，仍不可直接打开后台云传输。

### 各设备阅读与明确接续

`reading/<set>/<device>` 使用 `device-reading` 版本 1 快照。每条位置带文档 ID、文档版本、
UTC 阅读时间与 PDF 页码/文本锚点；不再携带资料库最近打开时间。文档版本由 ID、revision、
包内源路径、manifest 路径、layout 和页数确定，改标题不使位置失效，替换源文件则失效。
这仍不是附件字节摘要：相同路径被外部覆盖的检测需要后续资源 manifest，不能声称已校验文件内容。

该流只接受对应设备作者的单父历史，不能合并两个设备副本或用时间选赢家。
分叉、未知格式、缺失历史都保留并显示诊断。`requires` 绑定已接受的内容版本；
每条位置须与它引用的源文档匹配，接收端等待内容因果历史，不把阅读记录当作创建文档的依据。
旧候选快照保持原 ID，仅可作为祖先；旧 tip 不作为已校验进度提供，下次本机写入升级为新格式。
设备身份禁止 `/` 以免产生歧义 scope，检测发生在创建日志前；不会自动重命名已有身份或清除历史。

接收仅持久保存设备快照，不修改本机文档位置、不回声上传其他设备记录。
学习集删除只对本设备阅读流写墓碑；其他设备历史保留，不能因此恢复已删除学习集。
显式编辑会话中的阅读改动仅存 private set 快照，结束或重启封存才和最终内容同一记录发布；
取消后不会遗留引用临时文档的共享中间位置。其他领域仍各自需要补齐依赖/取消语义。

工作区“同步与恢复”面板提供“从其他设备继续”，显示文档名称、设备序号、时间及位置。
资料库尚无设备名称登记，因此序号只是当前列表标签，不是用户自定义设备名。
`ReadingContinuationRepository` 给 UI 类型化选项；选择携带观察到的远端 revision 和本机阅读 token。
仓库在学习集队列内检查当前文档版本、输入保护、主要资源存在性与版本前提。
准备成功只返回目标，阅读器实际导航后才记录本机进度；失败保留面板供重试。
PDF 防抖中的本机页码先保存，验证中发生新翻页、文本滚动或切换文档会拒绝迟到结果；关闭面板取消未完成的跳转。
文本接续先加载并校验 book/chapter，再定位 revision/chapter/offset；PDF 目前是页级接续。
主要文件存在不等于所有附件可用，损坏 PDF、图片缺失与按需下载还依赖后续资源子系统。

## 生词身份、来源与字段候选

`words/<identity>` 使用新 `VocabularyWord` v1 协议。identity 由规范语言和词形的规范摘要组成：
语言 trim、小写并将下划线替换为连字符；词形 trim、小写并折叠空白。不猜测语言别名，尚不做 Unicode NFC/NFKC。
现有本地文件保留原始语言拼写和 ID，只有显式启用日志后的迁移才建立规范身份。旧 UUID 作为不可删除 alias 保存在
词条历史里，唯一别名可解析到新词条；同一个别名对应多个存活词条时不随意跳转。删除词条不会删除这段历史。

每个词条有一个明确、确定性的空根 `vocabulary-baseline-v1`，只包含协议和规范身份，没有用户字段。
两个设备各自添加同词使用这一共同根。接收器可重建其精确提交；未知根仍拒绝，不以新空根替代未知用户历史。
基线是持久接收记录，不是本设备待上传内容；发送 `pending()` 的后继可以由接收器补出该已知数学根。
这个新领域协议尚未发布为长期兼容承诺。

释义、音标、词形、笔记、状态及存活状态各自保存不可变的作者写入与已观察删除集合。
同字段不同值保留全部候选，稳定排序仅提供显示值；普通输入只替换其观察到的显示值，不能清除未显示的候选。
明确选择需准确词条 revision，清除已观察的该字段候选；并发选择继续保留为字段冲突，不阻塞其他词条/字段。
删除与并发编辑保留“移除/保留”选择。术语展示、创建/修改时间仅做展示归并，不参与正文胜负。
多父提交必须是父状态的精确并集，不能制造写入或遗漏候选；单父后继不得改旧写入、伪造作者或删除未观察值。

来源保存完整摘录快照和文档/学习集身份；精确相同的规范快照去重，位置、时间或文本不同的来源全部保留，取消旧 20 条上限。
来源删除只移除已观察值，并发加入的来源仍在。来源是独立历史摘录，不要求原学习集仍存活，也不因接收摘录复活文档。
它不发布原文档的未提交内容；与工作区复合编辑的关系是独立的生词收藏操作，而不是把生词挂进工作区撤销事务。
旧版本已经裁掉的来源无法凭空恢复。源快照 ID 规范为内容摘要；原词条 ID 另存 alias。

本地旧聚合索引迁移时，同规范身份的多条词合并来源、保留字段候选，不简单选一个 UUID。
旧共享 `vocabulary` 聚合提交冻结，新共享索引不携带私有全文；旧远端聚合候选仍保留并报告不支持，完整图迁移尚未完成。
新词条版本、完整本机索引与待发版本在同一日志提交。投影失败可重试，收到远端版本不回声上传。
`AtomicVocabularyRepository` 在仓库队列读取最新状态后应用编辑；已建立词条历史后不再接受无前提的整份 `save` 替换，
避免旧快照删除刚收到的来源。普通本地模式仍保留原 `save`，不因此启用同步。

生词界面展示人可读的字段候选、输入中/修复/异常历史状态。笔记与简释输入先等待仓库屏障、重读后开放输入，
输入期间只暂缓该词条。失败缓冲和租约保留；另一字段保存成功不会把失败字段当成已保存。销毁等待在途保存后释放。
AI 释义更新检查原释义仍未改变，拒绝迟到覆盖。撤销在同队列校验受影响词条版本与观察值；即便收到的显示内容相同，
新贡献也会使旧撤销失效。其他词条的独立修改不影响该撤销。未提交/失败的键盘缓冲仍不是持久恢复草稿。

`FileSyncReceiver` 要求学习集和生词仓库共享同一个 ledger，把持久收件交给各活仓库发布并通知观察者，重试幂等。
它尚未接到云服务调度器，也不代表云端交付确认。历史写入/删除集合未压缩，尚无长期规模验收。

## 段落译文与人工内容保护

`TranslationRegister` 版本 1 使用 `translated/<set>/<document>/<language>`，每个不可变写入携带设备作者、
操作标识、文档版本、内容 key 和完整段落来源；删除是可传播的空值贡献。旧写入不能改删，观察删除集合只能增长。
文档版本采用阅读协议相同的 id/revision/fileName/contentManifest/layout/pageCount 摘要；这不是文件字节校验，
同路径外部覆盖仍需要资源 manifest。文档替换后不展示旧版本译文，原贡献仍保留在历史。

每个流有可精确重建的空 `translation-baseline-v1` 根，不为未知根猜基线。单父校验作者及观察删除，
多父必须是精确并集，不能用整合提交制造新译文。每个非根提交必须依赖已接受的学习集内容版本，
新增写入的文档版本必须与依赖内容吻合。乱序/缺依赖等待；非法、无/多基线及已删除分支保留诊断。
本机已有 JSONL/旧聚合内容在首次启用时与新共享版本同记录迁移，提交失败不留下空基线覆盖旧内容。
旧共享 `translations/` 图及原 ID 保留，不自动把旧远端聚合当成新协议应用，完整旧图迁移仍待完成。

人工编辑和明确删除优先于背景 AI；自动文本贡献保留但不能覆盖人工内容。相同文字去重展示、来源不丢失；
不同人工候选和并发明确选择都保留为段落候选，独立段落继续同步。稳定排序只确定当前显示项，不表示自动解决。
普通编辑只替换观察到的显示候选；明确选择校验该段落 token 后才移除全部已观察候选。
无观察前提的 append 只能增加人工贡献，不能隐式清除其他人的内容。

`GuardedTranslationStore` 提供类型化快照、观察 token、实时订阅和明确选择；调度器监听真实仓库，
在串行写入之后重读，不复用过期通知内容。AI 请求开始时捕获观察版本，迟到结果不能覆盖后来输入；
文档替换会使旧调度任务失效。保持相同对象身份只用于没有新贡献的刷新，远端同文字新贡献仍使旧 HUD 撤销失效。
调度器的 Isolate 准备工作放在仅包含可传递参数的函数中，避免新监听闭包导致捕获不可传递的 Future。

阅读器在原文旁展示候选文字/删除选项；打开输入时固定观察版本，远端更新不替换键盘缓冲。
过期保存保留输入并提示，退出输入后可重新对照；未保存键盘内容不是持久草稿。学习集状态包含当前文档的
译文冲突计数，不会在段落仍有候选时宣称没有冲突。该提示仍需用户进入译文阅读器，不是库级历史整理工具。

复合内容草稿期间拒绝新译文写入并暂缓远端应用；不发布依赖未完成内容的译文。
草稿中的临时文档删除不提前创建译文墓碑或清理文件；取消保留原译文，确认删除/重启封存时，
墓碑与最终内容在同一 ledger 记录提交，再清理投影。明确删除对并发人工修改保留选择，背景任务不能复活删除。
这完成了当前译文写入的依赖/取消规则，不等于所有业务域具有一个分布式原子事务。

## 服务传输与账号隔离

`FileSyncEngine` 提供显式 bind/resume/pause/run，连接库/生词共享的 `FileSyncReceiver`，不是只把下载内容塞进日志。
同实例并发 run 合并为一次工作；新绑定一律暂停，必须明确 resume。重启不会自行构造带凭据的适配器或开启后台任务。
本机 `connection.json` 保存服务、账号身份、位置、资料库、设备、修订与暂停状态，不保存 Authorization/password。
凭据仅留在本次 WebDAV 适配器实例中；之后设置流程应使用现有 SecretStore 并区分新建与连接已有资料库。
账号身份应来自实际认证主体，不是可随意复用的显示昵称。

交付记录按 target 摘要分文件保存，确认前在 ledger 队列再次检查连接修订。暂停/切换立即使在途循环失效；
已开始的对象 IO 可能仍在旧服务完成，但不会记到新账号，也不会继续发送下一对象。旧目标待发状态保留。
浏览器读取绑定直接查询 IndexedDB，不用标签页的旧缓存；另一标签页暂停后，旧标签页不能继续确认，旧缓存覆盖配置也被 CAS 拒绝。
原生仍要求单 ledger 实例所有权，不宣称跨进程协调。

共享目录为 `foliarc-v2/<library digest>/library.json` 与 `commits/<id>.json`。资料库声明必须完全匹配；
读回校验提交摘要、资料库、协议及允许的数据域。仅发送 `pending(target, includeDelivered: true)` 中本机生成的共享版本，
按父版本与 requires 拓扑排序，当前草稿保持暂缓。`library`、`vocabulary`、`translations/` 旧聚合仅作为本机迁移输入，
不传到新服务。每轮重新验证对象是否存在，远端已丢失的本机对象会重新创建，不把本机旧确认当成永久成功。
切换到空目标时若缺少本机并非作者的祖先，停止并保留队列，不能伪造祖先或上传 private 快照补洞。
这一限制需要后续显式整图迁移处理，不能冒充已经完成服务迁移。

早期 v1 提交仍保留原 ID；只要本机图包含 v1，本次传输在任何网络 IO 前报告 legacyProtocol。
下载 v1 也被拒绝，禁止跨 VM/JS 误验摘要、重算 ID 丢引用或清空历史。此为明确兼容门禁，不是完整图迁移。
`run` 返回本轮收到、确认及仍暂存数量，不表示资源已到齐或所有冲突已经解决。

WebDAV 使用 HTTPS、深度 1 的 PROPFIND、MKCOL 和 `If-None-Match: *` PUT。已存在对象先读回比较，
竞争创建后也读回确认；拒绝不同内容碰撞、重定向、外部 href、DTD、非法对象路径和超限响应。
适配器固定认证信息，不跟随重定向发送凭据；错误映射为认证、权限、配额、暂不可用等类型，不显示服务响应正文。
超时触发 AbortableRequest 取消；真实服务须正确实现条件创建，浏览器服务还须允许这些方法/头的 CORS。
协议依据 [WebDAV RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html)。目前验证使用可控 HTTP 客户端，没有配置真实 WebDAV 账号或完成服务联调。

iCloud 适配器有明确容器与账号的 `ICloudDrivePort`，检查操作前后账号身份，端口还必须在文件协调操作内部检查 expectedAccount。
本机 create/read 成功只返回 staged；资料库声明与提交均确认后才可 acknowledge。uploaded 必须在同一协调读取中
校验刚读回的确切字节、无未决文件版本/上传错误，并检查 [ubiquitousItemIsUploaded](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemisuploadedkey)。
原生端口应使用 [NSFileCoordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator)。
第十四批提供共享 Swift `ICloudDriveStore` / `ICloudDriveChannel`，已注册到 iOS/macOS Runner，
以及 `mm_platform` 的 `MMICloudDrive`。调用在串行工作队列执行；读取、创建及交付确认使用文件协调，
协调访问内部再次核对账号，拒绝符号链接、协调后改名、路径穿越及超限对象。新对象通过同目录临时文件、
同步刷盘和 `renamex_np(RENAME_EXCL)` 原子发布，已有对象绝不覆盖，再由 Dart 校验规范内容。
文件仍待下载或存在未决系统版本时保留待发状态；evicted placeholder 请求下载后返回暂不可用，
不能把缺少本机字节当成可以覆盖的空对象。仅 `.current`、确切字节相同、无版本冲突和上传错误且
系统报告 uploaded 的版本允许确认。目录枚举仍受本机 iCloud 元数据可见性影响，不宣称已枚举完整云端历史。

账号使用 [ubiquityIdentityToken 的 isEqual 比较](https://developer.apple.com/documentation/foundation/filemanager/ubiquityidentitytoken)，
归档在本机 UserDefaults 并映射为稳定本机 UUID；不哈希归档充当跨设备用户 ID，不上传令牌或本机账号映射。
系统令牌变化在每次原生操作检查，设置层后续仍须接账号变化通知与暂停提示。

部署保持 macOS12/iOS17。原生桥接仅接受构建时 `FOLIARC_ICLOUD_CONTAINER_IDENTIFIER` 对应的 Info.plist 配置，
不能由 Dart 任意指定容器。该构建变量默认未设置，`configured()` 返回 null，不尝试访问用户 iCloud。
要做真实验收，需在两个 Runner 的 Xcode Signing & Capabilities 中启用 iCloud Documents，
选择开发团队实际拥有的同一容器，让 Xcode 生成匹配的签名 entitlement/provisioning，并将构建变量设为该容器 ID。
本 PR 没有添加虚构容器、修改开发者账号、启用 Share Extension 的 iCloud 权限或配置真实用户账号。
**原生代码与本机文件协调可以测试，签名容器、系统上传确认、跨设备真实 iCloud 流程尚未验收。**

当前每个对象最多 16 MiB、目录最多 100000 个提交；仍全量枚举/重放历史，收件批次尚无增量游标和规模验收。
资源未传输、设置/同步状态 UI 未接入这些新端口，因此默认产品仍不能开启完整后台云同步。

## 第十六批：资源清单、不可变块与按需下载

`sets/<id>` 的可选 `resources` 字段使用独立版本 1，按文档内容版本、图片卡片或研究快照分组。
清单与本机 set 快照、共享候选版本在同一 ledger 记录落盘；普通内容写入保留仍适用的分组，
删除/替换只去掉过期引用，不删除原文件或历史。旧内容没有清单时仍可读取本机文件，但不会宣称资源已经验证。

前台传输先在真实 set 写队列准备资源。只读取当前内容明确引用的路径，以及书籍 `manifest.json`
和网页 `resources.json` 明确列出的依赖；不递归扫描目录，不读取其他包或 `.foliarc-sync/local`。
文档清单依赖的路径、摘要必须一致。原生拒绝仓库内符号链接；路径前缀、穿越、扩展名、清单数量和文件长度有边界。
每个文件记录实际 SHA-256、长度及固定 4 MiB 块，单文件上限 1 GiB，清单最多 10,000 个分组/文件。
原生文件流式计算；浏览器仍会把单文件放入内存，尚不满足大文件规模验收。

块先保存到 `.foliarc-sync/blobs/<hash>`，再提交引用它的清单。这个目录是可重建的资源缓存，不是私有恢复日志。
上传只取待发共享提交中清单列出的块；WebDAV、iCloud Dart 和 Apple 桥接白名单明确增加
`blobs/<sha256>.bin`，没有开放任意文件路径。每轮对每个不同块校验/发送一次，避免同一资源在多个历史快照中重复往返。
只有资料库 manifest、提交及其全部块均由服务确认，才确认该提交；iCloud 暂存仍保留待确认。
新目标缺远端作者祖先的门禁不变，不能把资源支持解释为已经完成服务迁移。

下载由用户明确选择资源组触发，使用当前连接目标、账号/暂停代际与资源版本前提。
先下载并校验块，缓存可跨重启继续使用；损坏缓存视为缺失，可重新下载。
组装后再次校验完整文件摘要，在 set 队列重新确认文档仍存在、版本未变且编辑已结束，再原子发布各文件。
暂停/换账号会拒绝后续读取和发布；已经发出的服务 IO 不能撤回。
包内已经存在且摘要不符的文件不会被覆盖。部分文件完成、后续中断时，清单仍显示未完整下载，重试只补缺失部分；
这不是整包多文件原子替换。尚无资源缓存回收/配额设置/历史压缩，不删除历史仍引用的块。

设置页提供“已校验 / 尚未完整下载 / 本机文件不符 / 尚无清单”和按需下载入口。

下载完成会通知当前阅读器重新检查。阅读接续也要求已知清单的完整资源可用；文本资源读取验证清单摘要。
翻页不会重新散列整本文件，但打开文件、检查状态和同步准备会读取字节；没有持续监视外部文件替换，规模与性能尚待验收。

## 第十七批：设备名称与账号生命周期

`FileSyncDevices` 用原 ledger 原子保存名称版本与待发记录，接收采用版本前提并通知已有订阅。

名称不要求全库唯一，不作为接续选择的身份前提；实际动作继续使用设备身份、远端 revision 和本机阅读 token。
设备登记沿共享提交正常上传，接收不产生回声；旧共享协议和私有日志传输门禁不变。

Apple 通道增加独立事件流，监听 `NSUbiquityIdentityDidChange`，只发送无个人信息的失效信号。
事件在主线程交付，不排到可能等待文件下载的串行 worker 后面，取消订阅移除 observer。
产品在 iCloud 连接探测之前订阅，恢复已有 iCloud 绑定时也订阅；账号通知或事件流错误立即使当前代际失效、

## 第十八批：原生取消与期限反馈

每次 iCloud 文件/身份请求使用独立随机标识；取消仅针对该 Dart 端口已经发出的请求快照，不影响之后的请求或其他端口。
原生主线程注册请求、处理取消及 30 秒期限，串行文件 worker 继续负责实际 IO。取消调用真实 `NSFileCoordinator.cancel()`，
操作令牌在容器解析前后、协调体内、读取/下载前以及临时文件刷盘后的发布前检查；原有账号、路径、不可变创建前提继续保留。
配置读取不进入文件 worker，故文件等待不会拖住未配置状态检查。

回调只消费一次。取消或期限到达先给界面返回类型化失败；worker 的迟到结果不再返回成功。
原生保留已取消请求直到物理 worker 退出，最多容纳 8 个请求，避免系统调用卡住时反复点击堆积无界载荷。
串行 worker 并未被假装终止：容器解析、已经进入的文件操作仍可能继续，队列饱和时明确拒绝新工作，直到系统返回。
这与 [Apple 对 NSFileCoordinator.cancel 的定义](https://developer.apple.com/documentation/foundation/nsfilecoordinator/cancel%28%29) 一致：
尚未开始的协调可停止等待，已经执行的访问块仍须结束。已发出的不可变文件可能留下完整对象，但不会因此确认交付。
本实现没有用单独的 `Future.timeout` 将未结束的原生写入伪装成已停止。

设置中的暂停、账号变化和控制器销毁都请求原生取消，同时继续使传输代际失效并持久暂停。
取消桥接失败时仍保留版本/目标前提与待发送记录；不声称底层已停止。
发现端口和恢复绑定期间追加代际检查，避免暂停之后又订阅迟到端口或开始新的账号查询。
超时文案说明待同步变更保留、系统操作可能仍完成，并允许重试；账号变化仍需用户明确重新连接。
本批没有改变云确认规则，也没有连接真实账号或上传用户资料。

## 第二十二批：并发人工选择的事务隔离与再次确认

此前两个设备对同一待处理事务作出选择，会使整个分支以 concurrentResolutions 保留，
连同该分支之后无关的改名也不能发布。现在重放递归追踪 resolves 指向的原始事务，
将尚未再次确认、彼此并发且关联相同原始事务的人工选择组成组；每个选择本身作为 pending 保留。
它们不按提交 ID 或时间判胜负，也不部分执行原子事务；后续不依赖这些字段的事务继续重放。
相同内容的并发选择也保留待确认，不能把显示去重当成人工决定已合并。

候选仍保存在不可变提交与祖先中，检查点必须准确携带全部 pending，不能以新合并提交隐藏候选。
对选择再作选择时，递归保留原始事务的修改路径以及选择自己的附带修改；这包括没有文本差异的“保留当前”。
候选预览因此能显示实际意图，而不是空白差异。整个实体的修改涵盖子路径，删除不会因随后应用旧子路径而重建空实体。
选择只替换这些路径，保留无关后续修改；结构仍须通过领域校验。

学习集和文件夹仓库在既有写队列中读取当前已接受图，以 expectedRevision 检查界面前提，
一次明确选择同时记录该组当前已观察的所有 resolves，版本、私有快照和待发送记录继续同次提交。
界面说明这一组确认范围，仍显示人可读的当前/候选内容，不要求用户依据摘要决策。
第三设备之后才送到的选择不包含在此前确认里，会与新的人工选择形成可再次查看的候选组；历史不丢弃。
不同原始事务的选择组互不影响；原子选择同时涉及多个原始事务时按关联闭包一起确认。

最终实现保持既有单父提交的差异重放规则和提交格式，不重写旧提交 ID。

## 第二十三批：资料库级已删除内容的显式副本恢复

新增可选 `LibraryRecoveryRepository`、真实仓库实现及资料库侧栏“已删除内容”入口，
即使所有学习集都已删除也能打开。默认本地模式不启用日志或恢复入口；导航只查询轻量能力，
打开面板才读取历史，避免侧栏每次刷新重建整份因果图。状态订阅复用带取消和串行刷新的类型化监听器。

恢复列表取已接受学习集头的完整祖先，按因果关系为每个已删除文档保留最近仍包含它的版本，
并为已删除学习集保留最近内容版本。先删文档、后删整个集合不会丢掉较早文档的恢复选项。
面板显示原名称、文档名、数量和卡片摘录，明确未决选择仅复制该版本的显示内容，原候选仍保留。
这不是任意历史版本浏览器，也不把未接受、无共同祖先或删除对编辑的异常分支直接接入已接受谱系。

用户明确选择后创建**新学习集身份**，内容实体保持包内引用，原学习集/文档删除记录、候选和附件不改。
副本进入未分类；复习评分、阅读进度及独立译文不复制。新的复习基线、内容快照、待发送记录和私有恢复回执
在同一 ledger 记录提交。恢复 ID 由库、设备、来源版本确定；回执不在 wire 白名单中，
只有新副本正常共享内容会进入传输。重试、双击或重启不创建第二个副本，不覆盖副本后续修改；
副本已被删除时不暗中复活它。原历史保持原身份，未伪造共同祖先，也未把同身份删除冲突宣称为已解决。

恢复在来源/目标写队列执行，以来源准确本机 revision、目标和回执不存在作同次提交前提，

文件投影失败不撤回已提交的副本，重启可恢复；提交前失败可重试，保留原内容和已验证缓存。
界面保留失败输入，显示过期前提或存储/资源失败；取消并重新选择才取得新观察版本。
