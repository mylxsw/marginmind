# 跨设备同步：实现状态与协议

关联 GUL-604。用户已确认修订方案，实施按“本地基础 → 服务接入 → 多设备验收”推进。

## 当前交付边界

目前已实现协议、合并、安全撤销、可恢复仓库提交，以及学习集/文件夹远端接收、事务隔离、复习事件重放与冲突/恢复面板。
**尚未开启云端同步，也没有配置或上传任何用户账号数据。** 默认资料库继续使用现有本地模式；
显式提供 `FileSyncLedger` 后才启用日志模式，重启从身份文件恢复。应用还没有提供开启同步的界面。

## 内容与设备状态

文件格式 11 的 `StudySetContent` 继续作为本地模型。同步投影把集合按稳定 ID 编码为字典；
节点使用 `(mapId, cardId)`，译文缓存使用 `(documentId, targetLang)`，排期使用 `cardId`。
笔记章节和块分别保存 `items` 与 `order`，正文修改不因数组位置变化而寻址到另一条记录。
未知集合、重复身份与字典键/实体 ID 不一致均拒绝解析。

`sharedContent` 排除阅读位置、最近阅读时间、折叠状态、复习三组数据、助手执行回执及本机对照配置。
`materializeShared` 恢复本机阅读与折叠状态、保留独立管理的复习数据。复习事件使用下述专用协议；生词和新译文存储的
专用合并协议仍需接入；当前投影里的 `translationCaches` 仅是旧格式缓存。
日志已经分开保存 `sets/<id>`、`reading/<id>/<device>`、`reviews/<id>`、`vocabulary` 和
`translations/<set>/<document>/<language>`。复习流使用共同基线与追加事件；
译文流保存段落及 origin，不保存任务 job 状态。不能仅凭数据分流就宣称领域合并已完成。

## 三方合并

- 一端未变时接收另一端；相同变化只保留一份；不同字段递归合并。
- 同字段不同值、删除与编辑并发、相同 ID 的不同新增记录产生显式冲突。
- `updatedAt` 只合并修改时间，不决定正文胜负，也不用于判断因果；`organizedAt` 是资料收集基线，
  并发不同基线必须保留冲突，不能按较晚时间自动选择。
- 有序笔记块的独立插入合并为稳定顺序；两端相互矛盾的顺序保留为冲突。
- 脑图同排序值使用稳定卡片 ID 作为第二排序键。合并后校验环、父节点、图/卡片/文档引用、
  关系线、概要（含概要节点的子节点）、书签、研究笔记关联及文本标注 revision；
  还校验批注的文档/节点、笔记中指向摘录/自有内容的活引用和章节交叉引用。

`ContentMergeResult.content` 是预览。字段冲突保留基线值，同时返回包含双方候选的 `SyncConflict`；
结构校验失败则 `content == null`。调用者必须先保存冲突及输入版本，不能将预览当成无冲突的提交。
纯快照合并函数只处理一个输入单元；学习集仓库现在按单次仓库提交重放原子修改，让无关事务继续同步。
工作区显式编辑会话已把跨多次仓库写入组合成一个共享内容事务；其他编辑入口仍需逐一接入并验收。
没有共同祖先、或有多个最大共同祖先时，调用者必须保留分支，不能随意选一个基线。

## 安全撤销

每次本地操作记录前后字段差异。撤销与重做在仓库最新快照上校验预期值，然后一次性应用全部差异；
任何字段或引用约束不满足都不发布候选内容。事务只组合本地操作，不把操作间到达的远端变更纳入历史。
连续修改同一字段会合并，避免每次按键都永久保存一个完整正文副本。
校验容忍当前数据或原操作目标中已有的旧引用错误，但不能因后来加入的内容制造新错误。
解码不运行旧文件的概要自动修复，避免合并/撤销悄悄制造新的卡片。

阅读与复习不进入撤销；普通修改时间不是撤销前提。笔记 `organizedAt` 决定新材料收集范围，
必须参与条件修改及撤销；`updatedAt` 仅在整条笔记仍匹配操作观察到的版本时恢复，否则保留后续写入的时间。撤销新建父节点时，如果它被后来新增的节点引用，
会拒绝该步，以免制造孤立节点。既有菜单和历史工具栏通过 `UndoneNotice.conflict` 显示本地化提示。
工作区还监听共享历史的冲突事件，覆盖忽略返回 notice 的 HUD 和原生菜单入口。
取消事务遇到冲突时，保留已提交内容与条件历史、结束事务并提示，避免编辑状态关闭后历史永久锁住。

## 提交与日志

新提交使用协议候选版本 2，尚未发布为长期兼容承诺；读入仍识别早期版本 1。提交包含：

```
protocol, id, libraryId, scope, deviceId, sequence, parents, deleted, payload, pending?, resolves?, requires?
```

`id` 是提交体的规范编码 SHA-256；v2 对对象排序、区分 JSON 类型，并把有限数值编码为 IEEE-754
字节（零统一为正零，拒绝超过安全整数范围的数值），避开 Dart VM/JavaScript 对 1/1.0 和指数文本的差别。
字符串不能冒充数值，数组不能冒充对象。`parents` 排序并拒绝重复；读入重新校验摘要。
删除提交只能携带空 payload。账号密码、token、系统密钥不属于此结构。
`SyncGraph` 拒绝缺失父提交、跨资料库/数据域父引用，以及同设备序号分叉。比较版本使用祖先关系，
时间戳不参与版本胜负。多个共同祖先显式返回集合，避免隐藏 criss-cross 分支。

日志按 `SHA256([libraryId, scope])` 隔离，存储在指定根目录下的 `.foliarc-sync/`。
每条提交先写同目录临时文件、flush、rename；未完成的临时文件不属于已提交数据。
重启读取全部已提交文件并校验因果图，损坏数据报错，不能静默覆盖或当作空资料库。
`pending()` 返回未确认的已提交版本；`acknowledge()` 只保存交付确认，不删除合并所需的历史。
调用者必须在云端确认持久化后确认交付，不能在 iCloud 本机暂存成功后确认。

当前日志采用单实例串行所有权；原生多进程、多实例写入不在本批承诺范围。
文件 flush + rename 覆盖进程中断恢复，不把它宣传成所有文件系统的掉电事务保证。
原生端仍要求一个资料库由同一 ledger 实例管理；应用启动时把它同时传给学习集与生词仓库，
译文仓库由学习集仓库传递该实例。并发原生进程写入尚不支持。

### 真实仓库提交与恢复

`.foliarc-sync/identity.json` 固定资料库及设备身份；缺失身份但已有日志时拒绝降级为普通本地模式。
身份不匹配会停止写入，不能把另一账号或资料库的队列接过来。服务账号绑定仍需在接入层实现。

`.foliarc-sync/local/<hash>.json` 是本机事务事实，包含顺序、前驱、多个数据域的本地完整快照及
新生成的共享提交。**这些日志文件不能上传**；发送端只读取 `pending()` 返回的共享提交。
无需另写 outbox；本地状态和待发送版本要么一起存在，要么都未提交。仅本机字段变化可以更新本地快照，
不产生共享内容提交。`expected` 版本前提与领域校验在同一队列内执行，过期候选不允许覆盖当前版本。

原生端以 flush + rename 为提交点；Web 把记录与 `.head` 比较标记放在同一个 IndexedDB 事务内，
防止旧标签页在过期版本上另开分支。事务提交之后的 `.mmset`、生词 JSON、译文 JSONL 写入失败，
不会把已经提交的操作误报为失败；错误保存在 `projectionErrors`，读取和重启使用日志中的数据。
学习集和生词在加载时重建投影；译文读取日志，后续写入或整理时重建文件。

创建、元信息、内容与删除都已改成提交后发布内存和通知。文档包先准备不可变附件，再提交元数据；
提交后的投影失败不会回滚已经被引用的附件。删除学习集时，内容、阅读、复习及已知译文墓碑同事务记录，
保留附件供后续恢复；删除文档也同步记录相关译文墓碑。子数据范围在 ledger 提交队列内确定，
覆盖排队期间刚创建的译文，不能先取快照再异步删除。译文写入在同一队列中再次检查文档生命周期，
拒绝迟到写入复活已删除内容。普通本地模式仍按既有策略删除文件包。

原有资料库首次进入日志模式会建立学习集及已有译文基线；生词首次加载/保存时建立基线。
初始化中的可重试投影/译文基线错误可查询，产品开启流程必须展示并处理这些错误，不能假装全部初始化成功。
当前保留所有本地历史；压缩、其他领域的远端应用、跨设备事件去重及规模测试仍未完成。

### 远端接收与学习集应用

本机日志新记录使用版本 3，仍能重放版本 1、2；不支持新版本的旧客户端拒绝读取。
版本 3 增加本机恢复通知及确认记录，不进入待上传列表。版本 4 使用新的跨运行时摘要，
旧 v1/v2/v3 本机记录继续按旧算法校验，旧提交 ID 和父链不改写；后继可使用新协议。
接收记录保留不可变远端提交，允许乱序到达，不把“收到”当成“应用”。随后根据完整祖先关系计算候选，
学习集写队列中的提交再校验预期本地 revision；若已经变化，就从日志中的最新快照重新合并。
成功后再更新资料库内存并通知 `watch`，投影失败保持已提交结果，重启可恢复。

快进直接采用已有远端版本，不制造回声上传；并发独立修改生成引用双方父版本的新提交。
待发送列表只包含本机新生成的版本。处理候选时先尝试后代，再处理祖先，避免已收到合并结果时
仍为旧父版本制造交叉合并；坏的或缺少祖先的后代也不能隐藏可应用的祖先。

缺失祖先、无共同祖先、多个共同祖先、设备身份分叉、删除/编辑、字段或结构冲突均保留输入。
诊断跟随日志持久化；重复输入不重复生成诊断，已纳入成功结果的诊断在同一提交中清除。
未知提交若使用本机设备身份则拒绝接收；其他设备的异常分支保留诊断，不阻止在已接受谱系上继续本机编辑。
阅读位置、复习和本机显示状态不被内容应用覆盖；文档 revision 改变后不沿用旧阅读锚点。
远端文档、图片及研究快照引用必须是包内相对路径；资源解析也拒绝路径穿越及跨平台绝对路径。

`canApply` 仍可供外部调度器暂缓应用；仓库还会检查实际编辑会话及实体保护租约，不能由调用方省略回调绕开。
**此 API 仍不是完整同步引擎**：目前应用 `sets/`、`reviews/` 与 `folders/`，其他领域收到后保留但不发布；
尚未具备生词、译文、阅读的远端领域处理器及资源可用性门禁。

### 资料库文件夹与归属

文件夹以 `folders/<id>` 独立保存 `{id, name}`。空设备没有文件夹根提交，可以直接接收已有文件夹；
不同文件夹的创建/改名互不阻塞。不能把每台设备自行建立的空 `library` 快照误认为共同历史。
旧 `library` 流不再随文件夹修改产生共享后继；它的本机快照仍保存完整文件夹索引，
和对应文件夹版本在同一个 ledger 记录中提交。旧本机索引在加载时建立一次 per-folder 基线，
不重写旧提交及父引用。早期仅有 `library` 共享快照的远端分支仍未自动迁移，不能把这种兼容读取
宣传成旧候选完整图迁移；服务开启前仍需迁移或明确门禁。

接收沿用因果图/事务重放：名称冲突保留双方候选，显式选择携带所见 revision；其他文件夹继续处理。
名字、身份、字段和祖先均校验，不接收额外私有字段或文件夹外部依赖。无共同祖先、多基线、
并发选择、删除对改名仍保留分支并显示说明，尚未提供这些异常分支的整理工具。

删除文件夹不删除学习集，也不批量改写学习集原始 `folderId`。摘要在所指文件夹尚未到达或已删除时
显示“未分类”；原始归属保留，乱序到达后可以恢复显示。明确移动才修改学习集的共享元信息，
并校验观察到的原始归属和目标是否存在；即使不同未到达文件夹都显示“未分类”，也不能绕过过期校验。文件夹登记队列先于学习集写队列，避免验证后目标立刻被本机删除。
这是可容忍乱序的归属引用，不是文件夹与所有学习集之间的分布式原子事务。

管理入口在可选组织端口可用时显示，本地模式也可使用，不因此开启同步日志。删除前说明学习集会保留。
名称输入保留打开时的版本；收到远端更新不替换输入，过期保存拒绝并保留文字。
冲突只展示当前/候选名称，不让用户按摘要 ID 作选择。文件投影故障可重试，重启以日志重建索引。
活动文件夹被删除时切到“未分类”并保留搜索条件。此面板不是已删除学习集的全局恢复中心。

### 原子仓库事务与可传播冲突

学习集接收现在从完整因果历史重放单次仓库提交：单父提交代表一次编辑，其前提来自实际观察到的
父快照；多父提交是整合检查点，不当作第二次编辑。依赖先后确定后，以提交 ID 稳定排序并逐事务
校验字段与结构。一项修改有冲突时，整项暂不应用，后续只改其他字段的事务仍可应用。
例如两个合法脑图移动合并后会成环，则保留一个有效显示候选，另一个移动及同次写入的关联修改
一起进入待处理状态；后续学习集标题修改继续同步。这里的显示候选不是自动判定哪方胜出。

共享提交的可选 `pending` 保存未解决事务 ID；完整候选及其原始前提保留在不可变祖先中。
收到整合提交但缺少父版本时继续等待。新设备取得祖先后可以重建同一显示内容及冲突候选；
普通本地编辑必须继承待处理列表，不能借一次新编辑把旧冲突抹掉。
接收端在每个整合检查点自己的因果上下文内校验重放内容和待处理列表，拒绝省略冲突的检查点。
候选协议仍未发布；旧实现会因不认识新增字段拒绝这些提交，而非静默丢弃冲突状态。

`syncConflicts(id)` 查询事务候选；`resolveSyncConflict` 要求明确的本地 revision 和选择。
选择对方修改时仅替换该事务实际修改的路径，保留后来的无关修改；整个候选仍须通过结构校验。
选择保留当前内容也生成带 `resolves` 的因果提交。版本过期、结构无效或落盘失败时不发布结果。
尚有待处理事务时不能直接删除学习集，以免删除隐含解决冲突；清理选择后正常因果删除继续可用。
`ledger.issues()` 仍表示未应用分支的诊断，已经整合的未决事务由当前提交的 `pending` 表示，
类型化状态和学习集面板同时展示两者，不能把 `issues` 为空解释为没有冲突。

当前边界仍需完成：剩余输入保护、混合分支的更细粒度暂缓、资料库级异常分支恢复入口。
两端并发作出冲突选择暂保留分支并报告 `concurrentResolutions`；不能静默选一个，但也还没有
细粒度协调这些选择。无共同祖先/多个最大共同祖先仍保留分支。涉及旧删除后复活的复杂历史
不自动猜基线。重放目前保留完整历史并重复验证检查点，尚未完成增量缓存、压缩及规模验收；
不能直接据此开启用户后台同步。

### 工作区编辑会话与本地草稿

`ContentEditRepository` 是可选端口，不改变普通仓库的 update 约定。工作区最外层 begin/commit/abort
对接真实仓库边界：每次更新仍将完整本机快照写入同一 ledger，但 `draft` 期间保持原共享提交不变；
结束时才从最终内容生成一个共享提交。创建节点/概要后输入标题因此不再发布中间半成品。
成功取消并恢复原内容时没有新的共享内容提交。提交失败保留会话供重试；取消的反向写入已成功后，
即使最终发布失败，重试也不会再次应用反向修改。跨引用窗口沿用既有的同学习集共享编辑历史。

草稿是本机记录标记，不能上传。本机 pending 查询暂缓该学习集及其 reading/reviews/translations
记录；不能把 .foliarc-sync/local 当作传输目录。重启时从最后保存的草稿恢复并封存一个内容事务，
`recoveredEditingDrafts` 暴露尚未确认恢复的学习集 ID，学习集面板提供持久确认。其他领域的临时记录、依赖顺序
与取消后收敛仍需在各领域处理器中完善，不能据此启用后台传输或宣称跨领域原子发布。

内联卡片、关系线和概要输入持有按稳定实体路径的租约，包含已有的关联卡片/概要/批注/标注。
开始输入前等待已经在途的仓库写入，再读取最新快照；之后触及这些实体或删除学习集的远端版本
暂缓，无关实体/元信息可应用。接收规划后在 ledger 队列中再次检查租约，避免检查与提交之间新开编辑。
创建类编辑的整个复合事务暂缓该学习集应用；结束或取消后对已持久接收的数据重新合并。
释放租约后的重试失败不会把已保存的本机编辑误报为失败；`editSyncErrors` 保留可查询错误，候选仍在日志。

卡片详情的标题/正文、研究笔记标题/正文、学习笔记标题/章节/Cornell 字段/文本块也已接入。
共享 `ContentInput` 在屏障后从仓库读最新内容，不依赖上一帧 widget 快照；活引用块还保护实际引用的
卡片/批注/研究笔记。先保护块再读取最新引用并获取来源保护，避免在途写入改变来源 ID 后保护旧对象。
保存失败保留输入和保护供重试；保存期间禁止再次提交和格式修改。销毁控件时，已开始的保存完成后才
解除保护；卡片详情保留既有关闭保存行为。尚未提交的学习笔记/研究输入关闭时仍按原行为取消，不宣称
键盘缓冲已持久化为恢复草稿。无同步端口的仓库保持原有即时编辑体验。

这仍不是全部输入控件的完整协调：独立 PDF 边注、标签/元信息弹层等入口还需审计；
一个远端快照同时含受保护修改与后续无关事务时，仍可能暂缓到当前输入结束。
当前租约是实体级保护，不应宣称已实现任意字段、任意远端分支的局部应用。

### 同步状态、冲突选择与恢复确认

`ContentSyncRepository` 是 core 的可选端口，UI 只依赖类型化状态和操作，不读取私有日志 JSON。
工作区侧栏和更多菜单在日志模式下提供“同步与恢复”；普通本地仓库不增加入口。
面板明确说明尚未连接云服务，待发送/无冲突均不表示云端交付成功。
状态订阅同时观察持久提交、输入租约、投影错误和交付确认；关闭界面后取消订阅。

当前提交的每个 pending 事务显示原始修改的全部字段，包括同次修改中的无冲突部分，
以当前内容和候选内容对照。关系引用转换成实体名称，章节/块展示文字，不要求用户解读哈希或 JSON。
候选结构不合法时禁用应用；输入期间禁用选择。保留/应用均带展示时的 revision，过期操作提示重新检查，
不能把新修改覆盖掉。尚未应用的分支以缺失历史、基线不明确、并发选择等独立提示保留。

重启封存草稿时，恢复通知与内容发布写入同一个本机事务；通知在再次重启后仍存在。
“已检查恢复内容”仅确认对应恢复标识，磁盘写入失败或新恢复替换了旧标识时不消除通知。
确认不产生共享编辑，不清除内容或历史。重试从日志修复学习集/译文/资料库文件，恢复失败的草稿封存，
再尝试已接收分支；投影失败不重复业务修改。保存成功但释放保护后协调失败也在面板显示。

该面板是学习集级入口，尚未覆盖无法打开或已删除集合的资料库级恢复中心；无基线、多基线、
并发冲突选择目前只能保留分支和说明原因，尚无进一步人工整理流程。复杂结构/资源差异只提供文字摘要，
未实现图形差异预览。账号连接设置、全局同步调度、资源可用性仍未接入，不能据此启用后台传输。

### 候选协议的跨运行时修正

本轮复核发现早期候选直接哈希 JSON，会因原生的 `1.0` 与 JavaScript 的 `1` 编码不同而拒绝同一提交。
协议 v2 改为上述带类型的规范摘要；内容比较也按 JSON 数值语义处理，不把整数/浮点编码差别当作编辑冲突。
固定摘要样例及原生生成的评分提交/排期样例同时在 VM 和 Chrome 校验与重放。
旧 v1 提交及 v1 冲突对象保留其旧算法和身份，新冲突对象版本为 2。本机 v3→v4 的恢复/后继写入有测试。
独立 FileSyncJournal 的目录名继续使用旧的字符串身份摘要，以免改算法后丢失已有目录。

早期 v1 候选没有可承诺的跨运行时数字格式；现在支持在原运行时继续恢复它们，**不宣称已修复旧 v1 的
跨运行时传输**。正式开启传输前，仍需把既有候选历史按验证后的完整图迁移或给出明确兼容门禁；
不得悄悄重算旧 ID、丢弃候选或清空历史。目前没有用户后台同步开启，也没有发布长期协议。

### 复习共同基线与评分事件

`reviews/<set>` 的 `review-events` v1 保存不可变共同基线、基线摘要，以及按评分 ID 保存的事件。
基线包含既有排期、记忆参数和原始日志；旧日志可能不完整，不把它们假装成可重新计算的全量事件。
沿用原文件读取器的确定性迁移，补齐缺失的旧记忆参数但不改变 due；已有日志仍可没有算法描述。
旧候选 reviews 快照通过一个明确的单父后继升级，新导入的本地资料直接建立基线。
尚未收到共同基线的设备可以编辑内容，但不能自行新建空复习历史后评分。

新评分记录保存 `foliarc-fsrs5` 算法版本 1、参数格式版本 1，以及完整权重、目标保留率、最大间隔。
评分事件还保存产生设备和已观察事件的因果前沿。调度/舍入/学习步骤的语义变化必须新增算法版本；
仅更换参数值也会保存在对应事件中，不能用接收设备的当前设置重新解释旧评分。
接收时校验作者、祖先、不可变旧事件、基线一致性、无环因果图；未知算法/参数版本保留诊断，不覆盖排期。
多父提交仅整合已存在事件，不能在检查点里凭空增添评分。无共同祖先或多个最大共同祖先仍保留分支。

重放先满足因果关系，再按原始 UTC 评分时间及事件 ID 排序独立事件；每选一个事件后重新计算可执行项。
设备时钟回拨不会让调度所用 lastReviewedAt 倒退；原始评分时间及当时观察的 intervalBefore/After 不改写。
每次重放都从共同基线计算，因此同一组事件在所有设备得到相同排期，重复接收不重复计分。
这项排序不用于正文冲突选赢家。评分历史不会复活卡片或学习集，已删除卡片的历史仍被保留。

`SyncCommit.requires` 显式记录跨域版本依赖；本地 `requireScopes` 在 ledger 原子提交队列内绑定，
可指向同一笔写入中新建/修改的内容提交。评分事件、本机排期和待发记录同一次落盘；投影失败只需修复文件。
接收复习版本先等待所引用内容进入已接受的因果历史，缺失内容/历史时持久等待，绝不以时间戳覆盖。
“已接受”包括携带 pending 的内容整合提交，并不替用户解决正文冲突；评分是独立历史，可能暂时对应
尚未显示或已删除的卡片，不因此创建该卡片。学习集删除仍由内容域拥有，迟到评分不能复活它。
不支持的反向或其他内容域依赖保留分支，不能跳过未知依赖直接发布。

复习应用与本机评分走同一个学习集写队列；提交前同时检查内容与复习 revision，版本变化后重读重放。
落盘后更新真实仓库内存及 watch；同步面板也显示复习流的未应用诊断。
当前 receiveSync/reconcileSync 的返回计划列表仍为内容域，复习问题通过类型化状态端口展示。
显式复合编辑期间暂缓复习接收，并拒绝新评分，避免对最终取消的临时卡片发布评分；提交/取消后自动重算。
普通实体输入租约不阻止独立排期更新，因为复习不改动输入正文或撤销历史。
保存失败时评分界面保留已翻开的当前卡片及队列，提示重试；保存中禁用评分并防止重复按键。
缺失基线或未结束编辑显示对应说明，旧会话的异步完成不会推进新会话。

尚未提供任意重置排期/覆盖记忆参数的共享事件，日志模式下不允许直接篡改排期或删改已记录评分。
默认本地模式仍保留原操作。独立历史、未知版本、删除后复活的人工整理流程仍需完善。
这只完成了复习对内容的依赖与编辑取消场景，不代表 reading/translations 等其他领域已完成原子发布。
历史校验和事件重放尚无增量缓存/压缩，未做大型资料库性能承诺，仍不可直接打开后台云传输。
