# 思维导图操作优化（一期）设计方案

> 建立日期：2026-10-29（GUL-562）。状态：**设计稿待确认**，确认后再拆分开发。
> 配套高保真原型：[`design/prototype/mindmap-phase-1.html`](../design/prototype/mindmap-phase-1.html)。单文件、无依赖，浏览器直接打开。右侧演示控制台有 9 个场景，每个场景附带规则和待确认项；所有操作都可以真实点按，⌘Z / ⇧⌘Z 可用。
> 依据：GUL-562 的需求与 XMind 截图、当前 `main` 的代码（`MapRelation` / `MapSummary` 已存在，`TreeLayout` 支持平衡布局）。本文不做工时评估。

## 0. 一页结论

- **一个入口：多选后出现的操作条。** ⌘ / ⇧ 点击或框选多个节点后，选区上方浮出“已选 N 个 · 合并 · 概要 · 关联 · 颜色 · 删除”。不能用的按钮变灰，悬停说明原因。不用记快捷键，也不用去菜单里找。右键菜单和快捷键也能用（合并 ⌥⌘J 新增；概要 ⌘]、关联 ⌥⌘R 沿用现有快捷键）。
- **合并：多段一张卡，每段都能回到原文。** 按导图顺序（不是点选顺序）拼接，每段换行。卡片里每一段都记得自己的出处：点哪段就跳到哪段原文，跨文档也能跳；反过来，点原文高亮会闪烁卡片里对应的那一段。合并时不弹确认框，直接执行，底部提示里可以撤销；之后想再分开，右键选“拆分”。
- **概要：从“一段标签”升级为“一个主题”。** 现在的概要只有一段文字。按 XMind 的做法，概要改为真正的主题：可以改名、Tab 添加细分主题、被关联线连接。选中括号后拖动两端，可以调整概要范围。
- **关联线：从节点上直接拖出来。** 选中节点后，右上角出现紫色 ⤳ 把手，拖到目标节点上松开即可，然后直接输入说明（也可以不写）。选中关联线后可以拖动两个控制点调整弯曲，并切换箭头方向、实线或虚线。
- **结构与配色：只做 4 种结构、6 套配色。** 结构有思维导图、逻辑图、括号图、树形图；配色有系统、多彩、清新、暖阳、莫兰迪、墨水，每套都有浅色和深色两个版本。入口在脑图右上角的“样式”，悬停预览，点击应用，可以撤销。摘录卡片左侧的色条始终是原文高亮色，不随配色改变。

## 1. 用户场景

| 场景 | 用户想要什么 | 对应功能 |
| --- | --- | --- |
| 同一个观点分几处摘录（跨段、跨页、跨书） | 合成一张卡复习，但仍能找回每一处原文 | 合并节点 |
| 一组摘录说的是同一件事 | 在旁边写一句总结，不改变原有的层级 | 概要 |
| 两个分支之间有因果、对照、反驳 | 画一条线并写上关系 | 关联线 |
| 读完一本书后整理笔记 | 换一种更适合阅读或打印的版式和配色 | 结构与配色 |

原则：选择越少越容易选，限制提前说明，所有操作都能撤销，原文锚点不丢。

## 2. 合并节点

| 项 | 规则 |
| --- | --- |
| 入口 | 多选操作条“合并”、右键“合并 N 个节点”、⌥⌘J。悬停“合并”时，用虚线框标出保留的那个节点 |
| 保留哪个 | 导图顺序（先序遍历）里最靠前的节点；它的位置、宽度、复习进度保留 |
| 文本 | 按导图顺序拼接，每段之间换行。摘录段落用宋体，主题或笔记文字作为“自己的话”段落，用系统字体，不能跳转 |
| 标题 | 取第一个非空标题（标题即复习题面） |
| 出处 | 每段保留自己的 `annotationId`。点某一段回到对应原文，⌘L 和右上角箭头回到第一段原文；出处行显示“文档 A、文档 B · N 处原文 · 已合并” |
| 原文 → 卡片 | 每处原文高亮仍然存在，点击时闪烁卡片中对应的段落 |
| 子节点 | 被合并节点的子节点按导图顺序挂到合并结果下 |
| 关联线 | 端点改为合并结果；自连线和重复的线自动移除，并在提示中说明 |
| 概要 | 范围收缩到剩余的同级节点；范围变空时，概要和它的细分主题一起移除，并在提示中说明 |
| 只有主题或笔记 | 合并为多行主题，不变成摘录卡片 |
| 不能合并 | 中心主题、图片卡片、概要主题（按钮变灰并说明原因） |
| 撤销 / 拆分 | 一步撤销即可完全恢复。“拆分”把每段变回一个相邻节点，但不会回到原来的位置 |

**待确认**

1. **复习进度。** 建议合并后沿用保留节点的 FSRS 进度；其余卡片的复习记录归档，不再参与排期。另一种做法是重置为新卡片。
2. **颜色。** 不同颜色的摘录合并后，卡片左侧色条取第一段的颜色，每段前面再用小圆点标出它原来的颜色。

## 3. 概要

| 项 | 规则 |
| --- | --- |
| 入口 | 多选操作条“概要”、右键、⌘]（沿用）；只选一个节点时也可以添加 |
| 范围 | 同一父主题下从第一个到最后一个选中节点之间的连续范围；如果包含未选中的节点，会提示“包含了中间未选中的 N 个节点” |
| 概要主题 | 创建后立即进入编辑，默认文字为“概要”；可以 Tab 添加细分主题，也可以被关联线连接。颜色跟随所在分支，各种结构下样式一致 |
| 调整范围 | 点括号选中概要，拖动两端的方块，自动吸附到同级节点；一次拖动算一步撤销 |
| 不能添加 | 中心主题、跨父主题、与已有概要重叠、对概要主题再加概要 |
| 布局 | 平衡布局下，被概要的分支排在同一侧，括号不会被中心主题切断（现有 `_split` 已考虑 summaries） |
| 删除 | 删除概要会同时删除它的细分主题；删除范围内的节点时，范围随之收缩 |

## 4. 关联线

| 项 | 规则 |
| --- | --- |
| 建立 | ① 选中节点后，从右上角 ⤳ 拖到目标节点（拖动时虚线跟随鼠标，目标节点高亮）；② 选中两个节点后点“关联”，方向从先选的节点指向后选的节点；③ 右键“添加关联线…”或按 ⌥⌘R 后，再点目标节点（沿用现有行为）。Esc 取消 |
| 外观 | 紫色虚线加箭头，和分支线区分开；默认向远离中心主题的一侧弯曲，减少穿过分支 |
| 编辑 | 选中后显示两个控制点；下方小工具条：单向箭头、双向箭头、无箭头、交换方向、实线或虚线、编辑说明、删除。双击线条或说明可以编辑说明 |
| 控制点 | 只有用户拖过才保存，保存为相对两端节点中心的偏移；没拖过的线随布局自动计算，切换结构后不会变形 |
| 去重 | 同一对节点只保留一条线，重复建立时选中已有的线 |

## 5. 结构与配色

结构：

| 结构 | 说明 | 适合 |
| --- | --- | --- |
| 思维导图 | 中心向两侧展开（当前默认） | 发散、总览 |
| 逻辑图 | 全部向右，折线 | 按顺序阅读的笔记 |
| 括号图 | 父主题与子主题之间用大括号 | 分类、拆解 |
| 树形图 | 自上而下缩进，类似文件目录 | 长摘录卡片、窄窗口、打印 |

配色：系统（现在的样子）、多彩、清新、暖阳、莫兰迪、墨水。配色决定中心主题、一级主题、分支线和概要的颜色；摘录卡片的色条、高亮色和关联线的颜色不变。

- 入口：脑图右上角“样式”。弹层打开时，脑图缩放到能看到全貌；悬停即预览，点击后才应用，鼠标移开就恢复。
- 作用范围：每张脑图分别保存，可以撤销；导出 PNG / PDF 时按当前结构和配色。
- 不做：XMind 的几十种结构变体和自定义配色编辑器（一期）。

## 6. 对现有代码的影响（开发时细化）

| 位置 | 变化 |
| --- | --- |
| `mm_core` `Card` | 新增 `segments: List<CardSegment>`（`text`、`annotationId?`），单段卡片保持现有字段并兼容旧数据；原文到卡片的反查改为查找所有段落 |
| `mm_core` `MapSummary` | 新增 `cardId`，指向概要主题卡片；细分主题以普通 `MapNode` 挂在该卡片下。旧数据里的 `label` 迁移为卡片标题 |
| `mm_core` `MapRelation` | 新增 `arrow`（end / both / none）、`solid`、`control1/2`（可空的偏移量） |
| `mm_core` `MindMap` | 新增 `structure`、`palette`，与 `density` 并列 |
| `mm_core` editor | 新增 `mergeCards`、`splitCard`，范围调整复用 `MapSummary.copyWith(fromId, toId)`；每个操作都是一步撤销 |
| `mm_layout` | 新增向右（逻辑图、括号图）和自上而下（树形图）两种布局，概要节点改为可以带子树 |
| `mm_design` | 配色令牌分浅色和深色；彩色配色下的文字对比度加入 `tokens_test` 检查（≥ 4.5:1） |
| 应用 | 多选操作条、关联线拖拽把手、概要范围把手、“样式”弹层、右键菜单项、⌥⌘J |
| 导出 / 大纲 | 导出按当前结构和配色输出；大纲视图里，概要显示为范围下方的一行“概要：…”，细分主题缩进在它下面 |

## 7. 已知问题与风险

1. 合并会让卡片变长：超过 4 行沿用现有“展开全文”。
2. 关联线跨越很多节点时会遮挡内容，所以默认弯向外侧，必要时由用户拖开。
3. 节点折叠时，关联线改连到折叠后可见的祖先节点（原型未演示）。
4. 原型的原文栏用纯文本代替 PDF 页面；节点拖动、大纲视图、导出这些现有能力没有在原型里重做。
