# iPhone 系统呈现改造

本轮接续 [原生呈现研究](ios-native-presentation-review-2026-11-02.md)，将原生参考接入正式业务。验收截图和运行记录归档于 [本轮证据](evidence/ios-native-presentation-2026-11-02/)。

## 呈现与业务的边界

应用继续使用一个 Flutter Engine 和一份业务状态。iOS 层只负责系统材质、表单、列表、确认与颜色选择，数据校验和读写仍由现有 Dart 控制器完成。没有再启动一份应用来承载弹层。

| 场景 | 手机处理 |
| --- | --- |
| 新建学习集 | 系统来源选择；系统文件选择；原生名称、网址表单；结果交回现有创建流程 |
| 添加网页、重命名、书签/目录条目编辑 | UIKit Sheet，medium/large 高度、拖动把手、原生输入框和键盘；错误不关闭表单 |
| PDF 与其他文档导航 | UIKit 可伸缩列表；类别菜单选择目录、书签、批注或缩略图；定位后关闭；“更多”保留完整管理工具 |
| 悬浮阅读与脑图工具 | iOS 26 起使用实际 UIGlassEffect；旧系统使用系统标准材质；不再绘制仿玻璃高光边缘 |
| 自定义颜色 | iPhone 系统颜色选择器；沿用现有批注、下划线与脑图背景的保存动作 |
| 阅读更多、脑图样式、导出与复杂表单 | 统一底部呈现与滚动；iOS 使用 Cupertino Sheet 路由；正文保持实色 |
| 助手、对象详情 | 保留现有业务与内容渲染，恢复中等/展开高度及拖动入口；键盘输入和横屏使用完整可用高度；草稿保留 |
| 设置 | 完整页面的分类列表与返回层级；标准大小的开关与手机字号；长标签换行；保留保存、放弃和草稿规则 |

助手、设置正文、阅读器和脑图画布仍由 Flutter 渲染。系统 Sheet 和系统材质的证据与 Flutter 交互的证据分开记录，不将 Cupertino 组件称为 UIKit 原生组件。

## 关闭、输入与状态

- 原生表单在提交前调用现有业务校验。错误显示在原表单，输入内容与键盘焦点保持；取消和下拉退出有未保存确认。
- 原生结果只完成一次；关闭后移除表单校验与缩略图回调，避免后续任务收到旧结果。
- 目录浏览复用阅读控制器定位；批注定位沿用原有行为。排序、编辑、批注整理等操作在完整管理页面保留。
- 系统缩略图按需请求，原生图片缓存限制数量；重排文档预览使用独立的临时绘制会话并释放图片和绘制资源。
- Flutter Sheet 额外保护 PopScope：拖动和滚动到底部的关闭动作不能跳过退出保护；降低动态效果时使用零时长路由过渡。
- AI 助手快捷动作在手机上可以换行，避免字号增大后挤出屏幕。

## 平台隔离

Dart 按 `MMInput.phone` 判断手机，iOS 桥接再次检查 `UIDevice.userInterfaceIdiom == .phone`。窄屏 iPad 不会被当作 iPhone；iPad 和 PC 保留原有布局分支。Android 使用自身的底部面板与 Material 开关，不调用 iOS 通道或原生材质视图。
