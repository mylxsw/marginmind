六条架构约定
1　单向数据流 UI 只发命令，不直接改状态；变化从数据库流回界面。
2　SQLite 是唯一事实来源 内存里不保存第二份业务数据。drift 的响应式查询负责推送，原文和脑图两个面板自然同步。
3　所有写操作都是命令 每个命令在一个事务里执行，并给出逆命令，撤销 / 重做自然成立。
4　第三方库藏在接口后面 pdfrx、drift 都只出现在基础设施层。将来在 Apple 平台换 PDFKit，只需新写一个 PdfEngine。
5　耗时任务进 Isolate 文本抽取、全文索引、缩略图、布局计算都不占 UI 线程，保证滚动和拖拽 60fps 以上。
6　不做同步，但不堵死同步 ID 用 UUID v7，每行带 updatedAt 和软删除标记。成本很低，以后加同步不用改表结构。

前端 = desktop + mm_features + mm_design
后端 = mm_core + mm_layout + mm_data + mm_pdf
平台 = mm_platform（只被 desktop 引用）
依赖规则
mm_core 零依赖。只用 Dart 标准库，可在命令行里直接跑全部用例测试。 前端不认识 drift 和 pdfrx。mm_features 只能 import mm_core、mm_design、mm_layout，以及 PdfEngine 接口提供的页面图像。 后端不认识 Widget。mm_data、mm_pdf 只实现 mm_core 定义的端口。 只在组合根里装配。apps/desktop 是唯一同时知道所有包的地方，用 ProviderScope 的 overrides 把实现注入接口。 用工具强制规则。在 analysis_options 里加 import 规则检查，越层 import 直接报错，不靠自觉。 边界可以搬家。以后要把后端放进后台 Isolate，或者换成远程服务，只需替换 StudySetService 的实现，前端不改。
